# 卡点验收清单（G1 ~ G5）· v1.0

使用方式：AI 执行到阶段末尾时逐项勾选（`- [ ]` → `- [x]`），全部通过才算过卡点。
勾选结果复制到 `output/<项目名>/` 对应文档中留存。**任何一项无法通过：停在当前阶段，修复或向用户升级。**
宪法（`constitution.md`）未通过 = 所有卡点都不通过。

---

## G1 Spec 评审（S0 → S1）

- [ ] 服务目标一句话说清（为谁解决什么问题）
- [ ] **已完成外部调研并落盘 `knowledge/research/YYYYMMDD-主题.md`**：含同类系统/选型/已知坑参考与来源链接（宪法 P11）
- [ ] spec 明确引用了调研要点（至少 3 条可追溯，标注来源）
- [ ] 用户故事完整（作为〈角色〉我要〈能力〉以便〈价值〉），覆盖主要路径
- [ ] 每条功能点附**可测验收标准**（怎样验证它做对了：请求/响应/数据状态），可逐条追溯
- [ ] 明确列出了"非目标"（本期不做什么）
- [ ] 边界与异常场景已列出（非法入参/空数据/并发/依赖故障/数据量级）
- [ ] 已判断服务/接口类型并对照 `patterns/api-patterns.md`，标注引用了哪些既有模式
- [ ] 缺失信息已向用户提问并得到回答，或明确标注为"按 XX 假设推进"（开放问题清单）
- [ ] spec 已落盘 `01-spec.md`，且每条验收标准可对应到宪法原则（P3）

## G2 架构评审（S1 → S2）

- [ ] 领域边界清晰：核心实体/聚合已识别，业务概念有统一命名（统一语言）
- [ ] **架构参考了真实案例**：调研笔记中有同类系统的成熟方案，差异点已说明（P11）
- [ ] 每条 spec 验收标准在架构中有对应承载模块（与 01-spec 交叉核对，无遗漏）
- [ ] 架构模式选型有理由（单体分层 / DDD / 微服务），复杂度与选型匹配，不过度设计
- [ ] 已引用该领域的成熟模式（`patterns/api-patterns.md`），偏离模式处有理由
- [ ] 外部依赖已列全（数据库/缓存/消息队列/第三方服务），各依赖的故障影响有预案
- [ ] 技术栈选型已查 `tools/toolchain.json`，引入清单外技术已登记
- [ ] 与 `knowledge/cases/` 中相似项目对照，吸收了既往经验

## G2b 数据与契约评审（S2 → S3）

- [ ] 表结构满足：字段类型明确、必填/默认值标注、索引覆盖主要查询路径
- [ ] 所有响应结构与错误码均来自 `conventions/response-and-errors.json`（无自造格式）
- [ ] 每个接口契约包含：方法、路径、入参（含校验规则）、出参、错误码、鉴权方式
- [ ] 写操作标注了幂等策略（幂等键/去重机制），跨表操作标注了事务边界（P8）
- [ ] 列表接口有分页契约；大字段/敏感字段有裁剪或脱敏说明（P6/P7）
- [ ] 契约变更流程已约定：冻结后变更须走变更记录并通知消费方
- [ ] 契约已落盘 `03-契约定义.md`

## G3 开发自测（S3 → S4）

- [ ] `05-tasks.md` 存在：任务粒度小且可审查，每任务自带完成定义（测试命令/验收脚本）（P4/P5）
- [ ] 任务全部完成或明确移交；**偏移日志**已记录：实现中发现的需求偏移都回流到了 spec/契约更新（P10）
- [ ] 服务在本地可运行，核心接口可用测试命令跑通
- [ ] 单元测试覆盖核心业务逻辑（Must 任务对应逻辑全部有测试），测试全部通过
- [ ] 代码中无硬编码配置/密钥/魔法错误码（P1/P6）
- [ ] 未重复实现 registry 中已有模块；新模块已登记（P2）
- [ ] spec 每条验收标准有对应实现或明确豁免说明（P3 可追溯）
- [ ] 无循环内查库（N+1）；列表查询已分页（P7）
- [ ] 代码规范检查通过（lint/format），无 TODO/FIXME 残留未登记

## G4 测试走查 + 验收（S4 → S5）

- [ ] `knowledge/checklists/backend-qa.md` 全部检查项通过（或明确豁免并注明原因）
- [ ] 已对照 `patterns/api-patterns.md` 该接口类型的"常见坑"逐条核对并记录结论
- [ ] 集成测试通过：真实数据库/依赖环境下的完整请求链路
- [ ] 边界情况验证：非法入参、空数据、并发重复提交、依赖服务超时/故障
- [ ] 安全基线通过：注入防护、越权测试（改他人 ID 访问）、日志无敏感信息（P6）
- [ ] 性能预算核对完成（P7，未达标有豁免说明）
- [ ] 走查结果落盘 `04-走查报告.md`
- [ ] 用户/产品方验收签字（或用户明确表示通过）

## G5 复盘关闭（S5 完成）

- [ ] 线上冒烟验证通过（核心路径可走通），回滚预案已验证或已文档化
- [ ] 复盘已写入 `knowledge/cases/YYYYMMDD-项目名.md`，三个反思问题已回答
- [ ] 积累池回写完成：新模块→registry、新问题类型→backend-qa 清单、新模式→patterns、改进的提示词→prompts、新规范→conventions
- [ ] 若有影响后续的选型/结构决策，ADR 已写入 `knowledge/decisions/`
- [ ] 偏移日志中的教训已评估：需要的话更新 spec 模板（prompts/spec-from-requirement.md）
