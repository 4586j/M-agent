# 项目宪法（Constitution）

> 借鉴 Spec-Driven Development 实践（GitHub Spec Kit 等）并针对后端场景实例化：宪法是**凌驾于单次任务之上的不可协商原则**，spec、契约、任务拆解、卡点全部以它为依据。修改宪法属于结构性决策，须先写 ADR。

## 原则清单

| # | 原则 | 内容 | 如何检查 |
|---|---|---|---|
| P1 | 单一事实源 | 响应格式/错误码/命名只认 `knowledge/conventions/response-and-errors.json`；配置只认配置中心/环境变量，代码中禁止硬编码魔法值 | 全局搜索硬编码错误码/配置抽查 |
| P2 | 复用优先 | 写任何模块/中间件/工具函数前先查 `components/registry.md`，禁止重复实现 | 开发记录中列出所查组件 |
| P3 | 规格先行 | 无通过 G1 的 spec，不得进入架构与开发；spec 是约束 AI 产出的"可执行契约" | 产出物与 spec 逐条可追溯 |
| P4 | 小步交付 | S3 开发前必须有任务拆解，每个任务独立可审查、自带完成定义 | tasks.md 存在且逐项勾选 |
| P5 | 验证内建 | 每个任务/阶段必须回答"怎么证明做对了"（测试/契约/日志证据），证明方式写入交付物 | 卡点勾选项全部有证据 |
| P6 | 安全底线 | 所有入参必校验；SQL/命令注入防护；接口必鉴权（除非明确豁免）；日志不落敏感信息；密钥只进环境变量 | backend-qa.md 安全组 |
| P7 | 性能预算 | 接口默认目标：P99 ≤ 300ms、列表类必分页、禁止循环内查库（N+1）、热路径有缓存策略；未达标须豁免说明 | 走查报告性能小节 |
| P8 | 幂等与一致性 | 写操作明确幂等策略；跨服务/跨表操作用事务或补偿；并发场景声明锁或乐观锁版本号 | 契约中标注幂等键/事务边界 |
| P9 | 积累义务 | 任务收尾必须按 AGENTS.md 第 4 节回写积累池，未回写 = 任务未完成 | G5 勾选项 |
| P10 | 偏移即停 | 实现中发现 spec 未覆盖或矛盾的需求：停下来更新 spec（记入偏移日志），禁止静默改需求 | tasks.md 偏移日志区 |
| P11 | 调研先行 | 架构/数据库/接口契约产出前必须完成外部调研：同类系统方案、框架选型证据、已知坑，并落盘调研笔记 | `knowledge/research/` 存在对应笔记，且契约/方案明确引用了调研要点 |

## 与流程的关系

- **spec（S0 产出）** 依据 P3 从宪法实例化而来：每条验收标准都能指出它服务哪条原则。
- **契约（S2 产出）** 是 spec 的技术化：数据库 schema 与 OpenAPI 接口定义冻结后才是"不可绕过的门禁"（API-First 实践）。
- **任务（S3 拆解）** 依据 P4/P5：每个任务自带验证方式（测试命令或验收脚本）。
- **卡点（gates.md）** 是宪法在各阶段的检查点实例。
- 冲突裁决顺序：用户明确指令 > 宪法 > spec/契约 > 历史习惯。偏离宪法必须在复盘与 ADR 中留痕。
