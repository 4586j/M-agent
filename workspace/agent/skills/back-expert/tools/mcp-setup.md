# MCP 接入说明

让 AI 直接连接后端开发环境的 MCP（Model Context Protocol）服务。按需接入，接入后在对应阶段的"AI 参与方式"中生效。

---

## 推荐接入清单

| MCP | 用途 | 生效阶段 | 优先级 |
|---|---|---|---|
| Postgres / SQLite MCP | AI 直连数据库：核对表结构、验证查询、检查索引与执行计划 | S2/S3/S4 | 高 |
| GitHub / GitLab MCP | AI 读取 PR、Issue、CI 状态；执行评审与合并检查 | S3/S5 | 高 |
| Postman MCP | AI 直接执行接口集合、跑联调用例、生成测试报告 | S4 | 中 |
| Playwright MCP | S5 冒烟验证：自动化走完整业务链路并截图/取证 | S5 | 中 |
| Docker MCP | AI 管理测试容器（集成测试环境的启停） | S4 | 低 |

## 接入步骤（通用）

1. 在 AI 工具的 MCP 配置中新增服务器条目（命令 + 参数 + 环境变量）。
2. **凭证安全**：数据库连接串、API Key 只放环境变量或本地配置，禁止写入本仓库任何文件（宪法 P6）。
3. 接入后做一次只读验证（如 `SELECT 1` / 列仓库）确认连通。
4. 在本文件"接入记录"登记：MCP 名、用途、接入日期。

## 安全约束（宪法 P6 的延伸）

- MCP 授予数据库权限时使用**最小权限账号**（开发库读写，不授生产库）。
- AI 经 MCP 执行的破坏性操作（DROP/DELETE/TRUNCATE/迁移回滚）必须先向用户确认。
- 生产环境一律不接 MCP。
