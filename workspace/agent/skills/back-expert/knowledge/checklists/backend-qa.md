# 后端走查清单（Backend QA）

S4 阶段逐项核对，全部通过（或明确豁免并注明原因）才能过 G4。
走查发现的**新问题类型**按积累规则追加到对应分组（AGENTS.md 第 4 节）。
勾选结果写入 `output/<项目名>/04-走查报告.md`。

---

## 第 1 组：安全（宪法 P6）

- [ ] 所有接口入参有类型/范围/长度校验，非法入参返回 PARAM 错误码而非 500
- [ ] 数据库访问全部参数化（无字符串拼接 SQL）；无命令注入/路径穿越风险
- [ ] 所有接口有鉴权；豁免清单（健康检查/公开接口）已显式列出并评审
- [ ] 越权测试：用 A 用户凭证访问/修改 B 用户资源，均被拒绝（横向 + 纵向）
- [ ] 日志与错误响应中无敏感信息（密码/令牌/身份证/堆栈细节）
- [ ] 密钥/凭证只存在于环境变量或配置中心，仓库与镜像中无明文
- [ ] 登录/敏感操作有限速；密码用加盐哈希存储

## 第 2 组：性能（宪法 P7）

- [ ] 核心接口压测/计时达标：P99 ≤ 300ms（或 spec 约定值），未达标有豁免说明
- [ ] 列表接口全部走分页；无全表扫描（主要查询有索引，执行计划已核对）
- [ ] 无循环内查库（N+1）；批量场景用批量语句/JOIN
- [ ] 热点读路径有缓存策略；写路径有缓存失效逻辑
- [ ] 慢操作（>300ms）已异步化；同步接口内无重活
- [ ] 连接资源（DB/HTTP 客户端/线程池）有上限与复用，无泄漏

## 第 3 组：一致性与幂等（宪法 P8）

- [ ] 写操作幂等策略与契约标注一致（幂等键/唯一索引已验证：重复提交不产生重复效果）
- [ ] 跨表/跨服务操作有事务或补偿；异常路径数据不留中间态
- [ ] 并发场景验证：同时提交同一写请求，结果正确（无超卖/重复/脏写）
- [ ] 状态机只允许合法迁移，非法迁移返回冲突错误码
- [ ] 异步消息消费端幂等；失败有重试与死信兜底

## 第 4 组：可观测性

- [ ] 请求日志包含：trace_id、入参摘要（脱敏）、耗时、结果码
- [ ] 错误日志带上下文（哪个接口、什么输入、哪一层抛出），500 有告警
- [ ] 关键业务事件有日志/指标（下单成功、支付回调、任务失败）
- [ ] 健康检查接口存在（依赖连通性可选）
- [ ] 无吞异常（catch 后既不处理也不记录）

## 第 5 组：契约与规范（宪法 P1）

- [ ] 实际响应结构与 `03-契约定义.md` 逐接口比对一致（字段名/类型/错误码）
- [ ] 响应包裹与错误码全部来自 `conventions/response-and-errors.json`，无自造格式
- [ ] 命名符合 conventions.naming（路径/表/字段）
- [ ] 契约变更已登记并通知消费方（前端/下游服务）

## 第 6 组：可维护性

- [ ] 分层依赖正确：接口层 → 应用层 → 领域层，无反向依赖（对照 registry 分层规则）
- [ ] 核心业务逻辑有单元测试；边界用例（空/极值/并发）有覆盖
- [ ] 配置外置：切换环境无需改代码；无硬编码魔法值
- [ ] 数据库变更走迁移脚本（可重放、可回滚），无手工改表
- [ ] 无未登记的 TODO/FIXME；复用模块已登记进 registry（P2）

## 第 7 组：前后端联调（来源：20260901 联调调研笔记，前端 agent 沉淀）

- [ ] 字段命名与契约逐字段一致（无 userId/user_id/userid 三方漂移）
- [ ] 类型与契约一致：时间统一 ISO8601 UTC 字符串；布尔统一 true/false；数字不返回字符串
- [ ] 分页结构符合 conventions.pagination（list/total/page/page_size），默认值与契约一致（page_size 默认 20）
- [ ] 空数据语义明确：列表空返回 `list: []`（非 null）；可选字段缺失返回 null 而非省略（契约有定义时）
- [ ] 错误响应也是统一包裹（前端拦截器可按 code 分支）；401 有明确的刷新/跳登录指引（契约 §0.2）
- [ ] 交付前端前附可跑通的入参示例（.http 或 Postman 集合），自证接口本地可用（联调准入规则）
- [ ] 契约冻结后的任何字段/默认值变更已走变更记录并通知前端（禁止前端 hack 适配）

## 第 8 组：实时长连接与时间驱动数值（来源：20260905 调研笔记 + pet-game 设计，对应 patterns 第 8/9 组）

### 8.1 WebSocket 长连接

- [ ] WS 房间/会话表在**两条路径**都有清理：连接异常关闭（onclose）+ 心跳超时（静默断开不触发 onclose），无房间泄漏
- [ ] 连接鉴权失败用自定义关闭码（如 4401）而非通用码，客户端能区分未登录与协议错误
- [ ] 帧长上限与频率限速在**服务端独立校验**，不只靠前端；超限回 error 帧而非直接断连
- [ ] 重连成功后**先推全量快照**再恢复增量；客户端在收到全量前丢弃增量帧
- [ ] 客户端退避重连带**随机抖动**（防重连风暴）且有上限
- [ ] 写操作不走 WS 上行（无幂等与事务保障），WS 只做通知与查询
- [ ] 广播在事务**提交后**执行；广播失败不回滚业务，只记日志
- [ ] 反向代理显式透传 `Upgrade`/`Connection` 头且 `proxy_read_timeout` 足够大
- [ ] NestJS `@nestjs/platform-ws` 已手动 `client.on('message')`（不会自动绑定，有回归测试守护）
- [ ] 单实例内存房间表已标注多实例限制与演进路径（Redis Pub/Sub）

### 8.2 时间驱动的服务端权威数值

- [ ] 时间结算**全部走服务端时钟**：接口无任何客户端时间入参，改客户端系统时间无法影响结果
- [ ] 时钟回拨（NTP 校正）已处理：dt 取 max(0, …) 且有 WARN 日志，数值绝不反向
- [ ] 结算用**闭式公式**而非按天/小时循环累加（离线 30 天与 30 秒耗时无差异）
- [ ] 数值有上下限 clamp（不产生负值或超上限）；累积类有每日上限且按 **UTC** 日界归零
- [ ] 参考值与结算时刻在**同一事务**内推进；读路径结算**不写库**
- [ ] 幂等键有**数据库唯一索引兜底**（不只依赖 Redis，Redis 丢数据也不会双写）
- [ ] 幂等命中时返回**首次执行的完整响应**而非报错（客户端重试无感）
- [ ] CD 与锁存服务端（Redis TTL），前端计时只做体验优化不作为唯一防线
- [ ] 缓存/锁依赖（Redis）不可用时业务**仍正确**（降级路径已测），不因依赖挂掉而 500
- [ ] 速率/上限/CD 等数值全部外置配置，代码内无硬编码魔法值
