# 提示词模板：Spec → 任务拆解（S3 前置）

用途：S3 开写代码之前，把 spec 与契约拆成小步、可审查、自带验证方式的任务清单（宪法 P4/P5）。
实现过程中本文件也是**偏移日志**的载体（宪法 P10）。

---

## 模板正文

```text
请在本仓库内按 AGENTS.md 约定工作，任务：把 spec 与契约拆解为后端开发任务清单。

【输入】
- spec：output/{{项目名}}/01-spec.md（已过 G1）
- 契约：output/{{项目名}}/03-契约定义.md（已过 G2b，或注明跳过原因）

【产出】output/{{项目名}}/05-tasks.md，结构如下：
1. 任务清单表格：编号 | 任务描述 | 完成定义（怎么验证） | MoSCoW | 依赖 | 预计产出文件
   - 拆解顺序建议：数据库迁移 → 领域逻辑（含单测）→ 应用编排 → 接口层
   - Must：spec 验收标准直接对应的任务，缺一个 G3 不过
   - Should：提升完成度但可延期；Could：锦上添花；Won't：本期明确不做
2. 实现顺序：按依赖排列，每个任务保持"半天内可完成、可独立审查"的粒度
3. 模块计划：列出将复用的 registry 模块与需新建的模块（新建即登记）
4. 偏移日志（预留空表）：时间 | 发现的问题 | 处理（更新 spec/契约的哪一条 / 向用户升级）

【规则】
- 每个任务的"完成定义"必须可执行：如"npm test -- order.test 全绿""POST /orders 重复提交同幂等键只产生一条数据"，禁止"完成订单模块"
- 任务中发现 spec/契约未覆盖或矛盾的需求：停下，先记偏移日志并更新 spec/契约，再继续（宪法 P10，禁止静默实现）
- 每完成一个任务即在 05-tasks.md 勾选并注明证据（测试输出/请求响应记录）
```
