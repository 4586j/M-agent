# 提示词模板：Spec + 架构 → 数据与契约（S2 入口）

用途：把通过 G2 的架构方案落成**冻结的契约**——数据库 schema 与接口定义（API-First，宪法 P1/P8）。
契约冻结后即为前后端/服务间的法律合同：前端可据此做 Mock 并行开发，后端据此生成代码骨架。

---

## 模板正文

```text
请在本仓库内按 AGENTS.md 约定工作，任务：基于 spec 与架构方案产出数据与接口契约。

【输入】
- spec：output/{{项目名}}/01-spec.md（已过 G1）
- 架构：output/{{项目名}}/02-架构说明.md（已过 G2）

【产出】output/{{项目名}}/03-契约定义.md，结构如下：
1. 数据库设计：每张表给出字段（类型/必填/默认值）、索引、关系，标注迁移策略（新建/变更）
2. 接口契约清单：每个接口包含——方法、路径、鉴权方式、入参（含校验规则）、
   出参（按 conventions.response_envelope 包裹）、可能的错误码、幂等策略（写操作必填）
3. 错误码映射：本服务用到的错误码全部来自 conventions.error_codes；需要新码先登记再使用
4. 契约变更记录（预留空表）：日期 | 变更内容 | 影响消费方 | 通知状态

【规则】
- 响应格式/错误码/分页/命名只认 knowledge/conventions/response-and-errors.json，禁止自造
- 每个写操作必须回答"重复提交怎么办"：幂等键或唯一约束，写进契约（宪法 P8）
- 列表接口必须带分页契约；敏感字段标注脱敏策略（宪法 P6/P7）
- 与 patterns/api-patterns.md 中对应类型的核心模式核对，偏离处写明理由
```
