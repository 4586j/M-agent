## 发现与可复用要点

### 1. 三条路的能力对比

| 方案 | 需域名 | 浏览器可信 | 成本 | 结论 |
|---|---|---|---|---|
| LE IP 证书（acme.sh shortlived） | 否 | 完全可信 🔒 | 免费 | **本次采用** |
| 自签名证书 | 否 | 报"不安全"，需逐端手动信任 | 免费 | 仅内部临时用 |
| LE / Cloudflare + 域名 | 是 | 完全可信 | 域名 ~10 元/年 | 有域名时首选（90 天/6 天均可） |
| 内网穿透（花生壳/ngrok/cpolar） | 平台代管 | 可信 | 免费额度限速 1Mbps、随机域名 | **不适用**：服务器本就有公网 IP，穿透是多余一跳，会压垮音频流 |

### 2. 关键机制与约束

- IP 证书**强制使用 shortlived profile**（有效期 6 天 ≈160h），这是 LE 对 IP 标识符的硬性策略，不能签 90 天
- 因此**自动化不是可选项而是前置条件**：`--days 3` 让 acme.sh 满 48h 就重签，cron 每日检查留出 2 天容错窗口
- LE Y 世系（Generation Y）中间 CA（本例 `CN = YE1`）已被 Windows/主流浏览器信任，实测严格校验通过，无需额外装根证书
- 换公网 IP ⇒ SAN 不匹配 ⇒ 必须重新签发

### 3. 落地清单（可直接复用）

1. Nginx **两阶段**配置：阶段 A 只在 80 端口加 ACME webroot 路径（站点持续可用）→ 签发 → 阶段 B 改为 80 只 301 + 443 全站
2. 签发：`acme.sh --issue --server letsencrypt -d <IP> -w /var/www/letsencrypt --certificate-profile shortlived --days 3`
3. 安装 + 续期钩子：`acme.sh --install-cert -d <IP> --fullchain-file ... --key-file ... --reloadcmd "systemctl reload nginx"`
4. 验证四件套：严格证书校验的首页 200、80→301、HTTPS Range 流、**wss 经反代**（TLS + Upgrade + 鉴权）
5. 混合内容扫描：全站代码不得残留 `http://` 硬编码

## 踩坑记录

- **国内云服务器访问 `raw.githubusercontent.com` 会静默挂死而非快速失败**：官方 `curl https://get.acme.sh` 卡住，脚本里 `curl ... || fallback` 的兜底分支永远不触发。必须：① 直接用 gitee 镜像 `git clone https://gitee.com/neilpang/acme.sh.git`；② 所有下载命令套 `timeout`
- `listen 443 ssl http2;` 是 Nginx 1.24 的正确写法；`http2 on;` 指令要 1.25.1+，版本混用会导致 `nginx -t` 失败
