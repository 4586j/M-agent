## 发现与可复用要点

### 1. Cocos Creator 是当前跨端 2D 养成游戏的成本最优解

- 一套 TypeScript 工程通过「构建发布」面板输出微信小游戏 / Web Mobile / Web Desktop / Android / iOS，引擎层适配由官方完成，业务代码无需改动。
- 构建面板配置是**平台相关**的：切换发布平台必须重新核对该平台的构建设置（这是高频踩坑点）。
- 包体优化四件套（小游戏平台）：① 项目设置 → 功能裁剪关掉未用模块（2D 游戏关掉全部 3D/物理/地形）；② Asset Bundle 分包 + 勾选「初始场景分包」；③ 勾选「分离引擎」用微信引擎插件显著减小主包；④ 大资源配 `remoteServerAddress` 走远程包，引擎自带下载/缓存/版本管理。
- 来源：[发布到微信小游戏 - Cocos Creator 官方文档](https://docs.cocos.com/creator/4.0/manual/zh/editor/publish/publish-wechatgame.html)、[Cocos Creator跨平台发布实战：从构建流程到性能优化](https://blog.csdn.net/aodanchui1057/article/details/102008691)

### 2. 装扮/换装的三种实现路线与其代价（本项目选型依据）

换装本质是「换插槽上的附件贴图」，三条路线代价差异极大：

| 路线 | 优点 | 代价 |
|---|---|---|
| Spine **整体换装** `setSkin()` | 实现最简单、三端统一、无需改引擎 | 需要 m×n 套完整皮肤：m 个部位各 n 种皮肤就要 m×n 份贴图，部件一多工程臃肿、图集失控、内存与加载双爆 |
| Spine **局部换装**（皮肤附件替换） | 可自由组合、部件可参与 Spine 合图减少 DrawCall | Spine 工程内要为每个部位出 n 个局部皮肤，美术维护成本高 |
| Spine **外部贴图换装** | 部件可用引擎 texture，与 UI 共用 | **原生端需定制引擎并重编译**（改 `SkeletonRenderer.cpp` 等）；改引擎后**小游戏端无法使用「分离引擎」**，直接拉长加载时间 |
| **分层 Sprite + 挂点**（本项目 Demo 选择） | 无需 Spine 授权与美术骨骼工程、无需改引擎、部件可懒加载、DrawCall 可控（同图集合批） | 部件不随骨骼动画形变（贴合类服饰会有穿帮）；部件多了要自己管 Z 序与挂点表 |

- 升级路径已明确：若正式版需要部件随动画形变，切 **Spine socket 挂点**方案（把 Cocos 节点挂到指定骨骼上），该方案**无需改引擎**，不影响小游戏分离引擎优化。
- 来源：[【方案】Cocos Creator 的 web/原生多平台 Spine 换装方案解析，附 Demo 源码](http://forum.cocos.com/t/topic/138623)、[Creator3.x Spine局部换装支持使用图集](https://forum.cocos.org/t/topic/166086)、[Cocos 官方技术方案分享（含 spine 使用非图集纹理局部换装 demo）](https://forum.cocos.org/t/topic/124637)

### 3. 时间驱动数值必须服务端权威（防作弊 + 离线结算）

养成类核心是「离线也在变化」，业界踩坑高度一致：

- **离线时长必须用服务端时间算**：用客户端 `Date.now()` / `os.time()` 会被改系统时间直接绕过。正确做法是存「上次服务端成功结算的时间戳」，用 `now(服务端) - last_settled_at` 求差。
- **收益/衰减需设上限截断**：离线 2 小时上线时按「离线时长 × 每秒速率」算理论最大值，超出部分截断，防挂机刷。
- **快速重连不要重复校验**：断线 2s 内重连时时间差过小，重复校验容易误判为作弊。
- 推论（本项目采纳）：**不存"当前值"，只存"参考值 + 结算时间戳 + 速率"**，任意时刻的值由纯函数惰性算出。这样既省掉扫全表的定时结算任务，又天然支持任意时长离线，且客户端无法伪造。
- 来源：[游戏断网也能玩还不怕作弊？聊聊我的离线存档防篡改方案](https://www.taptap.cn/moment/797819603542607222)、[游戏服务端之数值治理经验](https://segmentfault.com/a/1190000045262039)

### 4. 长连接同步：移动 Web/小游戏环境的断连是常态，不是异常

- 微信侧硬数据：基础库 1.7.0+ 最多同时 **5 个** WebSocket 连接；**小程序/小游戏进入后台约 5 秒即断开连接**。
- 移动浏览器同样会因切后台、锁屏、网络切换（Wi-Fi↔4G）静默断开，且不一定触发 `onclose`。
- 因此设计上必须：① 指数退避重连（1s/2s/4s/8s，上限 30s）**加随机抖动**防重连风暴；② 重连成功后**先收全量快照再恢复增量**（增量在断连期间必然丢失）；③ 服务端心跳判活并清理僵尸连接与房间表，否则房间泄漏。
- Nginx 侧必须显式透传 `Upgrade` / `Connection` 头，否则握手直接失败（本项目既有部署已验证此配置）。
- 来源：[wx.connectSocket 官方文档（并发数）](https://developers.weixin.qq.com/minigame/dev/api/network/websocket/wx.connectSocket.html)、[微信小程序实时通信：7个关键技术点](https://blog.csdn.net/gitblog_00222/article/details/157990008)、[环信 uni-app 全平台方案（各端小程序 WS 连接数）](https://docs-im-beta.easemob.com/document/applet/uniapp.html)、本机 `output/blog-backend/src/random-chat/random-chat.gateway.ts`

### 5. 微信小游戏的发行合规约束（当期不生效，保留为后续前置清单）

三条硬约束，任何一条不满足都无法正式上架：

1. **网络域名**：`wx.request` / `wx.connectSocket` 只允许 `https` / `wss` + **ICP 备案域名**，官方明确「域名不能使用 IP 地址（局域网 IP 除外）或 localhost」。
   → 本项目既有的「Let's Encrypt **IP 地址**证书 + acme.sh 自动续期」方案在微信端**直接失效**，上小游戏前必须购买域名并完成 ICP 备案（新备案域名需 24h 后才可配置，每月仅 50 次修改机会）。
   → 开发期可用微信开发者工具「不校验合法域名、TLS 版本及 HTTPS 证书」+ 真机调试模式绕过，但该选项**不影响正式提审**。
2. **类目与主体**：一级类目固定「游戏」不可改；**个人主体不支持「文化互动」「角色」「牌类」三类目**。「养成类」属三级类目，可挂在「休闲游戏」二级类目下。宠物养成存在被审核判定为「角色养成」而驳回的风险（开放社区已有「在非游戏类目小程序中添加角色养成对战功能属于违规」的官方答复）。
3. **资质与变现**：无内购（纯广告 IAA）时个人主体需《计算机软件著作权登记证书》+《游戏自审自查报告》+ ICP 备案；**一旦要做内购/虚拟支付，必须企业或个体工商户主体 + 游戏版号**（版号周期 4-6 个月）。注意 2026 年软著已从形式审查转向「有限实质审查 + 诚信监管」，补正率 60%+，纯 AI 生成代码会被认定无独创性驳回。
- 来源：[类目设置 - 微信官方文档](https://developers.weixin.qq.com/minigame/introduction/guide/type.html)、[网络基础能力 - 微信官方文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)、[域名管理 - 微信官方文档](https://developers.weixin.qq.com/doc/oplatform/developers/basic_func/domain.html)、[免版号！Unity 微信小游戏 个人主体接入发布全流程](https://blog.csdn.net/CSDNzhizunbao/article/details/164299647)、[微信开放社区：非游戏类目添加角色养成属违规](https://developers.weixin.qq.com/community/minigame/doc/00046aa4abcfa820f2f4c99de66800)
