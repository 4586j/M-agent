## 发现与可复用要点

### 1. erp-chat 组件盘点（本机源码）

- **定位**：客服型（访客 widget ↔ 坐席 agent），不是对等随机聊天；核心模型是"会话 + 坐席分配"，与"随机配对"语义不匹配
- **技术栈**：Java 17 + Spring Boot + MyBatis + MySQL（博客栈是 NestJS + SQLite，引入需新增 JVM/MySQL 运维）
- **值得移植的设计**（本次吸收进博客随机聊天）：
  - 帧协议风格：type 化 JSON 帧（message/typing/ping/pong/error/history）
  - 保活机制：25s 心跳 + 90s 无入站帧判僵尸关闭（`WidgetWebSocketHandler.sweepWidgetSessions`）
  - 限流分层：连接限流（IP）+ 发送限流（客户端+IP 双维度）+ typing 低优先级静默丢弃
  - 单条消息 2000 字上限
  - 会话写帧互斥（`synchronized(session)` 防并发写）
  - widget 嵌入式体验：右下角气泡 + 面板（tawk 风格，`widget.js`）
- 来源：本机 `D:\al\erp\heyan\erp-chat\src\main\java\com\erp\chat\ws\WidgetWebSocketHandler.java` 等

### 2. 随机配对聊天的业界共识

- **配对**：维护待匹配队列（FIFO），新用户入队时队列已有等待者则立即两两配对；否则停留等待并可提示"暂时没人"
  - 来源：[基于WebSocket的匿名匹配机制实现全解析](https://blog.csdn.net/alek_ovo/article/details/158575699)、[网页五子棋匹配模块](https://cloud.tencent.com/developer/article/2526320)
- **心跳判活**：客户端定期心跳，超时未收到判离线并从队列/会话移除；配对中一方掉线要通知另一方
  - 来源：同上（匿名匹配文）+ [如何快速实现一个聊天室](https://juejin.cn/post/6963447634870665230)
- **会话生命周期**：配对成功建立临时会话（sessionId 贯穿路由）；任一方离开/断开即结束会话并通知对方；消息不强制持久化（匿名阅后即焚取向）
  - 来源：[路过聊天系统技术解析](https://wenku.csdn.net/doc/1s16wn6t6q)、[树洞交友架构](https://blog.csdn.net/weixin_60938478/article/details/164090486)
- **防刷与匿名**：登录门槛（本项目用 JWT）+ 消息频率/长度限流 + 匿名代号展示（不暴露真实身份）
  - 来源：[路过聊天系统技术解析](https://wenku.csdn.net/doc/1s16wn6t6q)
- **规模适配**：单实例内存队列足够（个人博客并发量级）；多实例扩展再上 Redis 队列 + Pub/Sub（架构留演进口）
  - 来源：[树洞交友架构](https://blog.csdn.net/weixin_60938478/article/details/164090486)
