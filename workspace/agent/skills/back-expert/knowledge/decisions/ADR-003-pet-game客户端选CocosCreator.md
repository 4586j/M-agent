# ADR-003：pet-game 客户端采用 Cocos Creator 3.8.x（含"去掉微信端后仍保留"的复评）

- 日期：2026-09-05
- 状态：accepted

## 背景

双人宠物养成小游戏要求覆盖**移动端 + 桌面端**，核心表现是「宠物动画 + 分层部件换装 + 双人实时互通」。立项时还包含微信小程序/小游戏端，用户在方案确认后追加决策「**先不做微信小程序**」（2026-09-05），因此本 ADR 需要在"微信端缺席"的新前提下复评引擎选型是否仍然成立。

约束条件：
- 换装需要多图层叠加与 Z 序控制，宠物需要待机/进食/开心等动画状态；
- 一套代码要同时产出手机浏览器可用的竖屏 H5 与桌面浏览器可用的宽屏页面；
- 用户表述为「**先**不做」微信端，即保留后续补做的可能；
- 既有前端资产在 `D:\agent\web`（博客前端），后端资产在本仓库，二者均为 TypeScript 栈。

调研依据见 `knowledge/research/20260905-双人宠物养成跨端游戏选型与合规.md` 要点 1、2、5。

## 决策

客户端采用 **Cocos Creator 3.8.x LTS + TypeScript**，当期只构建 **Web Mobile** 与 **Web Desktop** 两个目标；平台差异全部收敛到 `platform/IPolicy` 适配层，`WechatPolicy` 保留为**显式抛未实现异常**的空壳，业务代码零平台判断。

**去掉微信端后仍保留 Cocos 的三条理由**：
1. Web Mobile / Web Desktop 本就是 Cocos 的一级构建目标，一套工程零改动产出两端，不构成"为了微信而付的溢价"；
2. 换装的多图层渲染、帧动画、图集合批、DrawCall 控制在 canvas 引擎里是原生能力，DOM 方案需要自己造；
3. 保留一键补做微信小游戏与原生 App 的能力——若后续确定永久放弃，再评估切换 Web-first 栈（见后果节的"复评触发条件"）。

## 备选方案（为什么没选）

- **Taro / uni-app（React/Vue）**：可复用既有前端技能栈、UI 组件开发效率高。放弃原因：① 宠物动画与部件换装只能用图片叠层 + CSS 动画，表现力与帧率控制弱；② 其核心优势（一套代码出小程序）在当期范围内**恰好失效**；③ 桌面端需要额外走 Electron/RN，反而多一层。
- **Web-first（PixiJS/Phaser 渲染 + React UI）**：Web 端最灵活、可迭代快，且能复用 React 技能栈。放弃原因：渲染层与 UI 层双栈协作成本（React 与 canvas 场景树的状态同步是持续的复杂度来源），且后续补微信小游戏时需要为小游戏容器重写适配层，等于两套渲染代码。
- **纯 DOM/CSS 方案（无引擎）**：最轻量。放弃原因：多部件 Z 序 + 动画 + 触控命中检测全部手写，且移动端浏览器 transform 合成层管理易出性能问题；省下的是依赖，付出的是自研成本。
- **Unity（WebGL 导出）**：生态最强。放弃原因：WebGL 包体与首屏加载对 H5 场景过重，且 TypeScript 生态与本仓库既有栈割裂（AI 生成质量与可维护性都不如 Cocos）。

## 后果

- **正面**：一套 TypeScript 工程覆盖当期两端并保留未来三端（小游戏/Android/iOS）路径；引擎层适配由官方维护；换装/动画/图集有成熟原生支持；`platform/IPolicy` 分层让后续补微信端只需新增一个 Policy 实现，不动业务代码。
- **代价**：
  - 与既有博客前端（React/Vue）技能栈**不通用**，需单独维护一套工程、构建链与资源管线；
  - Cocos 编辑器是 GUI 工具，场景/预制体的可视化编辑难以完全纳入 AI 自动化流程 → 已在 `05-tasks.md` 中把场景类任务的完成定义写成**可在浏览器预览中人工核对的行为断言**，而非纯自动化测试；
  - 构建面板配置是**平台相关**的（调研要点 1），切平台漏配是高频坑 → 已落为 T-38 的完成定义（构建参数留档）。
- **影响范围**：
  - `tools/toolchain.json`：**必须新增 `client-engine` 分类并登记 Cocos Creator**（清单外新工具，AGENTS.md §5 强制），备选记 Taro / uni-app / Phaser / PixiJS —— 已落为 T-01；
  - `output/pet-client/` 新工程目录；`02-架构说明.md` §3；`01-spec.md` §5 非目标（微信端、原生 App）；
  - `components/registry.md` 待登记 R-005（客户端平台适配层）。
- **复评触发条件**（满足任一时重开本 ADR）：
  1. 用户明确**永久放弃**微信小游戏与原生 App → 应评估切换 Web-first 栈以复用 React 技能资产；
  2. Web 端首屏加载 > 5s 或低端安卓机帧率 < 30fps 且优化无效 → 评估 Phaser/PixiJS 轻量方案；
  3. 后续补做微信小游戏时主包压不进 4MB → 需引入远程资源包与分包（调研笔记第 7 节核查清单）。
