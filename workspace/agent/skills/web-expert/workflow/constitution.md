# 项目宪法（Constitution）

> 吸收自 Spec-Driven Development 实践（GitHub Spec Kit 等，见 README 来源）：宪法是**凌驾于单次任务之上的不可协商原则**，spec、任务拆解、卡点全部以它为依据。修改宪法属于结构性决策，须先写 ADR。

## 原则清单

| # | 原则 | 内容 | 如何检查 |
|---|---|---|---|
| P1 | 单一事实源 | 颜色/间距/字号/圆角/阴影只认 `knowledge/design-tokens/tokens.json` | 全局搜索硬编码 hex/px 抽查 |
| P2 | 复用优先 | 写任何组件前先查 `components/registry.md`，禁止重复实现 | 开发记录中列出所查组件 |
| P3 | 规格先行 | 无通过 G1 的 spec，不得进入设计与开发；spec 是约束 AI 产出的"可执行契约" | 产出物与 spec 逐条可追溯 |
| P4 | 小步交付 | S3 开发前必须有任务拆解，每个任务独立可审查、自带完成定义 | tasks.md 存在且逐项勾选 |
| P5 | 验证内建 | 每个任务/阶段必须回答"怎么证明做对了"，证明方式写入交付物 | 卡点勾选项全部有证据 |
| P6 | 可访问性底线 | WCAG AA：正文对比度 ≥4.5:1、键盘可达、焦点可见、控件有关联 label | visual-qa.md 第 7 组 |
| P7 | 性能预算 | 首屏图片懒加载、无未压缩大图；条件允许时桌面 Lighthouse Performance ≥ 90，未达标须豁免说明 | 走查报告性能小节 |
| P8 | 三视口响应式 | 1280 / 768 / 375 全部不破版 | visual-qa.md 第 5 组 |
| P9 | 积累义务 | 任务收尾必须按 AGENTS.md 第 4 节回写积累池，未回写 = 任务未完成 | G5 勾选项 |
| P10 | 偏移即停 | 实现中发现 spec 未覆盖或矛盾的需求：停下来更新 spec（记入偏移日志），禁止静默改需求 | tasks.md 偏移日志区 |
| P11 | 调研先行 | 设计方案（spec/原型/视觉）产出前必须完成外部调研：竞品案例、设计模式、动效/视觉参考，并落盘调研笔记 | `knowledge/research/` 存在对应笔记，且 spec/原型/视觉稿明确引用了调研要点 |

## 与流程的关系

- **spec（S0 产出）** 依据 P3 从宪法实例化而来：每条验收标准都能指出它服务哪条原则。
- **任务（S3 拆解）** 依据 P4/P5：每个任务自带验证方式。
- **卡点（gates.md）** 是宪法在各阶段的检查点实例。
- 冲突裁决顺序：用户明确指令 > 宪法 > spec > 历史习惯。偏离宪法必须在复盘与 ADR 中留痕。
