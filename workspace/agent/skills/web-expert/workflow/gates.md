# 卡点验收清单（G1 ~ G5）· v1.1

使用方式：AI 执行到阶段末尾时逐项勾选（`- [ ]` → `- [x]`），全部通过才算过卡点。
勾选结果复制到 `output/<项目名>/` 对应文档中留存。**任何一项无法通过：停在当前阶段，修复或向用户升级。**
宪法（`constitution.md`）未通过 = 所有卡点都不通过。

---

## G1 Spec 评审（S0 → S1）

- [ ] 页面目标一句话说清（为谁解决什么问题）
- [ ] **已完成外部调研并落盘 `knowledge/research/YYYYMMDD-主题.md`**：含竞品/案例/模式参考与来源链接（宪法 P11）
- [ ] spec 明确引用了调研要点（至少 3 条可追溯，标注来源）
- [ ] 用户故事完整（作为〈角色〉我要〈能力〉以便〈价值〉），覆盖主要路径
- [ ] 每条功能点附**可测验收标准**（怎样验证它做对了），可逐条追溯
- [ ] 明确列出了"非目标"（本期不做什么）
- [ ] 边界与异常场景已列出（空态/加载/错误/极端数据）
- [ ] 已判断页面类型并对照 `patterns/page-patterns.md`，标注引用了哪些既有模式
- [ ] 缺失信息已向用户提问并得到回答，或明确标注为"按 XX 假设推进"（开放问题清单）
- [ ] spec 已落盘 `01-spec.md`，且每条验收标准可对应到宪法原则（P3）

## G2 原型评审（S1 → S2）

- [ ] 页面区块划分完整（头部/导航/主体/脚部/弹层等无遗漏）
- [ ] **原型参考了真实案例**：调研笔记中有该页面类型的优秀实例，差异点已说明（P11）
- [ ] 每条 spec 验收标准在原型中有对应承载区块（与 01-spec 交叉核对，无遗漏）
- [ ] 关键交互流（提交、跳转、异常路径）有状态说明
- [ ] 已引用该页面类型的成熟模式（`patterns/page-patterns.md`），偏离模式处有理由
- [ ] 移动端与桌面端布局意图都已明确
- [ ] 与 `knowledge/cases/` 中相似项目对照，吸收了既往经验

## G2b 视觉评审（S2 → S3）

- [ ] 所有颜色/间距/字号/圆角均来自 `tokens.json`（无临时值）
- [ ] 已复用 `registry.md` 中的既有组件，未重复设计
- [ ] 各状态（默认/hover/激活/禁用/加载/空态）有视觉定义
- [ ] 设计稿链接或截图 + 标注已落盘 `03-视觉稿.md`
- [ ] 新增视觉模式已同步回 tokens 并登记变更原因

## G3 开发自测（S3 → S4）

- [ ] `05-tasks.md` 存在：任务粒度小且可审查，每任务自带完成定义（P4/P5）
- [ ] 任务全部完成或明确移交；**偏移日志**已记录：实现中发现的需求偏移都回流到了 spec 更新（P10）
- [ ] 页面在本地可运行，无控制台报错
- [ ] 代码中无硬编码颜色/间距（全部引用 tokens 产物，P1）
- [ ] 未重复实现 registry 中已有组件；新组件已登记（P2）
- [ ] spec 每条验收标准有对应实现或明确豁免说明（P3 可追溯）
- [ ] 三种典型视口（桌面 ≥1280 / 平板 ~768 / 手机 ≤375）布局不破（P8）
- [ ] 组件 Props/接口与数据源对齐（无 mock 残留的 TODO 混入）
- [ ] 代码规范检查通过（lint/format）

## G4 视觉走查 + 验收（S4 → S5）

- [ ] `knowledge/checklists/visual-qa.md` 全部检查项通过（或明确豁免并注明原因）
- [ ] 已对照 `patterns/page-patterns.md` 该页面类型的"常见坑"逐条核对并记录结论
- [ ] 截图与视觉稿叠对比，明显偏差已修复
- [ ] 边界情况验证：空态、加载态、错误态、极端数据（超长文本/空列表）
- [ ] 可访问性基础项通过（键盘可达、对比度、焦点可见，P6）
- [ ] 性能预算核对完成（P7，未达标有豁免说明）
- [ ] 走查结果落盘 `04-走查报告.md`
- [ ] 用户/产品方验收签字（或用户明确表示通过）

## G5 复盘关闭（S5 完成）

- [ ] 线上冒烟验证通过（核心路径可走通）
- [ ] 复盘已写入 `knowledge/cases/YYYYMMDD-项目名.md`，三个反思问题已回答
- [ ] 积累池回写完成：新组件→registry、新问题类型→visual-qa 清单、新模式→patterns、改进的提示词→prompts
- [ ] 若有影响后续的选型/结构决策，ADR 已写入 `knowledge/decisions/`
- [ ] 偏移日志中的教训已评估：需要的话更新 spec 模板（prompts/spec-from-requirement.md）
