# 流水线定义（S0 ~ S5）· v1.1

前端页面设计制作的六阶段流水线。每个阶段定义：输入 → 工作 → 产出 → 退出卡点。
卡点的具体验收项见 `gates.md`。**卡点未全部通过，禁止进入下一阶段。**
所有阶段共同的上位依据是 `constitution.md`（项目宪法），冲突时按宪法"裁决顺序"处理。

```
宪法 constitution.md（贯穿全程）
      ↓
S0 需求→spec →G1→ S1 原型 →G2→ S2 视觉设计 →G2b→ S3 任务拆解+开发 →G3→ S4 走查与联调 →G4→ S5 上线与复盘 →G5(关闭)
```

> 阶段可跳过但必须记录：例如已有高保真设计稿时从 S3 进入，但需在任务记录中写明"跳过 S0~S2 的原因及对应交付物由谁提供"。

---

## S0 需求 → Spec（规格化）

| 项 | 内容 |
|---|---|
| 输入 | 用户/产品方的一句话或文档需求 |
| 工作 | **先调研**（宪法 P11）：上网检索同类页面案例与设计模式，调研发现落盘 `knowledge/research/YYYYMMDD-主题.md`；随后按 `knowledge/prompts/spec-from-requirement.md` 把原始需求规格化为 spec：用户故事、可测验收标准、非目标、边界异常、开放问题；对照 `patterns/page-patterns.md` 判断页面类型并引用既有模式与调研要点 |
| 产出 | 调研笔记 + `output/<项目名>/01-spec.md`（spec 是后续所有阶段的可执行契约） |
| 退出卡点 | G1 |
| AI 参与方式 | WebSearch/WebFetch 检索竞品与案例、结构化整理、生成疑问清单、对照 `cases/` 与 `patterns/` 找相似经验 |
| 宪法依据 | P3 规格先行、P11 调研先行 |

## S1 原型

| 项 | 内容 |
|---|---|
| 输入 | 通过 G1 的 spec |
| 工作 | **补充调研**：检索该页面类型的优秀实例与交互参考（Mobbin/Page Flows/Awwwards 等），记入调研笔记；页面结构草图（区块划分、导航层级、关键交互流）；移动端与桌面端两套布局意图；**先查 `patterns/page-patterns.md` 中该页面类型的成熟模式**，站在模式上做差异化而非从零发明 |
| 产出 | `02-原型说明.md`（区块级布局描述 + 引用了哪些模式与调研案例）或线框图文件 |
| 退出卡点 | G2（原型评审） |
| AI 参与方式 | 用提示词模板快速生成多版布局方案供挑选；工具参考 `tools/toolchain.json` 的 `ai-gen` 类 |

## S2 视觉设计

| 项 | 内容 |
|---|---|
| 输入 | 通过 G2 的原型 |
| 工作 | **补充调研**：检索目标风格的视觉/动效参考（获奖案例、动效趋势、可复用特效实现），记入调研笔记；基于 `knowledge/design-tokens/tokens.json` 出高保真稿；复用 `registry.md` 已有组件；新视觉模式须沉淀回 tokens |
| 产出 | 调研笔记更新 + 高保真稿（Figma/MasterGo 链接或截图）+ 标注说明写入 `03-视觉稿.md` |
| 退出卡点 | G2b（视觉评审） |
| AI 参与方式 | Figma MCP 读取设计稿；按 tokens 生成设计变体 |

## S3 任务拆解 + 前端开发

| 项 | 内容 |
|---|---|
| 输入 | 通过 G2b 的视觉稿 + spec |
| 工作 | ① 先按 `knowledge/prompts/tasks-breakdown.md` 把 spec 拆成小任务（每任务自带完成定义，MoSCoW 优先级）→ `05-tasks.md`；② 逐任务实现，页面代码按 `page-from-design.md` 模板生成；③ 实现中持续做**偏移检测**：发现 spec 未覆盖/矛盾的需求，按宪法 P10 停下更新 spec，记录到 tasks.md 偏移日志，禁止静默实现 |
| 产出 | `output/<项目名>/` 下可运行页面代码 + `05-tasks.md`（含偏移日志） |
| 退出卡点 | G3（开发自测） |
| AI 参与方式 | Vibe Coding：AI 生成 + 人工审核；选型查 `toolchain.json` 的 `dev` 类 |
| 宪法依据 | P4 小步交付、P5 验证内建、P10 偏移即停 |

## S4 走查与联调

| 项 | 内容 |
|---|---|
| 输入 | 通过 G3 的页面代码 + 视觉稿 + spec |
| 工作 | 按 `knowledge/checklists/visual-qa.md` 做像素级走查（有条件用截图叠对比工具）；**对照 `patterns/page-patterns.md` 该页面类型的"常见坑"逐条核对**；接口联调与边界情况（空态/加载/错误/极端数据）验证；修复后回归 |
| 产出 | `04-走查报告.md`（检查项勾选结果 + 截图对比 + 模式核对 + 修复记录） |
| 退出卡点 | G4（视觉走查 + 验收） |
| AI 参与方式 | 浏览器自动化截图对比、控制台报错扫描、清单逐项自检 |

## S5 上线与复盘（含反思环）

| 项 | 内容 |
|---|---|
| 输入 | 通过 G4 的最终版本 |
| 工作 | 构建、部署、线上冒烟验证；按 `knowledge/cases/TEMPLATE.md` 复盘，必须回答三个反思问题：① spec 中哪条验收标准被证明最有效/最没用？② 偏移日志里的需求为何当初没进 spec？③ 本项目出现了哪个可复用模式或反模式？ |
| 产出 | 上线地址/发布记录 + `knowledge/cases/YYYYMMDD-项目名.md` |
| 退出卡点 | G5（复盘回写完成） |
| AI 参与方式 | 部署脚本执行、冒烟测试、按积累规则回写积累池 |
| 宪法依据 | P9 积累义务 |
