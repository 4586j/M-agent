# 页面类型 UX 模式库

设计页面时的"先查库再动手"资产：每个页面类型给出**核心模式**（照着做）与**常见坑**（S4 走查逐条核对）。
使用时机：S0 spec 判断页面类型 → S1 原型引用模式 → S4 走查核对常见坑。发现新模式/新坑按积累规则追加。

## 1. 仪表盘 Dashboard

**适用**：中后台、数据监控、运营看板。

**核心模式**
- 先分辨类型：运营型（看当前状态）、分析型（看趋势归因）、战略型（看长周期目标），信息密度与时间范围完全不同
- KPI 卡片置顶：大数字 + 环比/同比 + 迷你趋势图
- 概览下钻：总览图 → 点击进入明细列表
- 全局时间范围选择器（默认近 7/30 天），所有图表联动
- 图表类型服务问题：趋势用折线、对比用柱状、占比用环形（≤5 项）

**常见坑（S4 核对）**
- [ ] 图表堆砌无主次：首屏超过 1 个主指标 + 4~6 个次级指标
- [ ] 数字无对比基准（没有环比/目标线，用户无法判断好坏）
- [ ] 无默认时间范围，首屏空白或全量加载过慢
- [ ] 空数据状态缺失（无数据时图表区空白无引导）

## 2. 落地页 Landing Page

**适用**：产品官网、活动页、获客页。

**核心模式**
- 首屏一屏说清：价值主张（一句话）+ 副标题（给谁解决什么）+ 主 CTA + 产品视觉
- 叙事结构：痛点 → 方案 → 功能亮点（配图）→ 社会证明 → 再一次 CTA
- 单一主 CTA 贯穿全页；次级动作（了解详情）视觉降级
- 社会证明具体化：用户数/企业 Logo/可验证的评价，不用空洞形容词
- 受众优先的信息架构：先想清楚来的人是谁，再排区块顺序

**常见坑（S4 核对）**
- [ ] 首屏 CTA 不明显或一屏内有多个竞争 CTA
- [ ] 文案自说自话（讲功能不讲用户价值）
- [ ] 图片无 alt、装饰图挤占 LCP
- [ ] 移动端首屏被大图占满，价值主张被推到第二屏

## 3. 列表 / 表格页 List & Table

**适用**：订单、用户、内容管理等中后台核心页。

**核心模式**
- 筛选区（高频 2~3 个筛选前置 + 更多筛选折叠）、排序、分页（后台数据用分页，不无限滚动）
- 列优先级：关键标识列 + 状态列 + 时间列 + 操作列，其余列可配置/隐藏
- 批量操作：勾选后浮出操作条，危险操作二次确认
- 行内快捷操作 ≤3 个，其余收进"更多"

**常见坑（S4 核对）**
- [ ] 列过多横向滚动，关键信息被挤出视口
- [ ] 筛选后无结果数反馈、无"清空筛选"
- [ ] 分页状态丢失（翻页后筛选条件被重置）
- [ ] 空态无引导动作（新建/调整筛选入口）

## 4. 表单页 Form

**适用**：注册、设置、各类创建/编辑页。

**核心模式**
- 单列布局优于多列（填写路径线性）；相关字段分组分步
- 渐进披露：高级选项默认折叠；条件字段仅在触发时出现
- 字段最少化：Baymard 研究显示多数表单可减 20~60% 字段，非必填不问
- 即时校验：失焦即校验、错误信息紧邻字段写清"怎么改对"
- 长表单分步时显示进度与可回退

**常见坑（S4 核对）**
- [ ] 校验只在提交时爆发，用户填完才知道错
- [ ] 错误提示只说"格式错误"不说正确格式
- [ ] 必填项过多或收集了用不上的信息
- [ ] 提交中无 loading 且可重复点击

## 5. 电商结账 Checkout

**适用**：购物车、结算、支付流。转化敏感型页面，模式都有数据支撑。

**核心模式**（依据 Baymard：全球平均弃购率约 70%，结账是最大转化杠杆）
- 访客结账：不强制注册，注册放在成交后
- 字段最少化 + 地址自动补全；能自动算的不让用户填
- 步骤指示器（当前/已完成/未到），每步聚焦一组决策
- 错误就近提示 + 保存已填内容（失败不回到空白）
- 费用全透明：早展示运费/税费，最后一步不加价

**常见坑（S4 核对）**
- [ ] 表单字段超 12 个（Baymard：复杂结账直接流失用户）
- [ ] 最后一步新增费用或要求注册
- [ ] 支付失败后已填信息丢失
- [ ] 无移动端专用优化（键盘类型、自动填充不生效）

## 6. 详情页 Detail

**适用**：商品、文章、订单详情、个人主页。

**核心模式**
- F 型信息分区：主媒体/主信息 → 关键属性 → 描述详情 → 相关推荐
- 关键操作固定可达（吸底 CTA / 侧栏操作卡）
- 元信息（状态、时间、归属）紧凑呈现，不与正文抢层级
- 上下文导航：面包屑 / 上一条下一条

**常见坑（S4 核对）**
- [ ] 长页面无吸底操作，读到底找不到 CTA
- [ ] 推荐区块打断主信息流
- [ ] 移动端主图与标题争抢首屏

## 7. 通用状态模式（所有页面类型共用）

空态/加载/错误/极端数据的完整核对项在 `../checklists/visual-qa.md` 第 6 组，此处只放设计模式约定：
- 空态 = 图 + 一句话 + 下一步动作（新建/联系/调整筛选）
- 加载 >300ms 才显示 loading；列表用骨架屏，按钮内用 spinner
- 错误态给"重试"和求助入口；区分网络错误与业务错误文案
- 极端数据测试点固定：超长文本、0 条、极大数字、emoji/特殊字符

## 8. 博客 / 内容站首页（沉淀自项目 blog，2026-08-30）

**适用**：个人博客、团队博客、数字花园的首页聚合页。

**核心模式**
- 排版驱动：大标题 + 宽松行高（正文 ≥1.7）+ 等宽字体点缀日期/数据/代码
- 首屏 = 身份卡：一句话身份 + 状态徽章（"正在写…"）+ 1~2 个 CTA，5 秒内说清"我是谁"
- 文章卡片四要素：标签 / 标题（≤2 行截断）/ 摘要（≤3 行截断）/ 日期 + 阅读时长
- 深色主题规范：近黑背景（#0a~#11）、柔和米白文字、低对比表面分层，强调色 ≤3 个
- 真人感区块：时间线/爱好/状态徽章等"个人信息"，是与产品官网最大的差异点
- 信息密度可以高，但每区块一个任务；滚动节奏 = 标题 → 内容 → 呼吸留白

**常见坑（S4 核对）**
- [ ] 文章卡片 meta 行未底部对齐（摘要行数不齐时参差）
- [ ] 装饰元素（光斑/粒子画布）把 scrollWidth 撑出横向滚动
- [ ] 动效只重形式不引导视线（违背"功能而非装饰"）
- [ ] 顶部导航高亮态在页面顶端失效（scrollspy 未含"首页"目标）

## 9. 虚拟宠物养成页（沉淀自项目 pet-client，2026-09-05）

**适用**：虚拟宠物/宠物共养/桌面宠物类的游戏互动主界面（非内容页，是"照顾循环"舞台页）。

**核心模式**
- 照顾循环闭环同屏：宠物舞台 → 数值条 → 动作按钮垂直排列在一屏内，"数值在哪、按钮就在哪"，动作结果立刻反馈到数值条 + 宠物动画 + delta 浮层
- 数值条语义色固定且低值告警：每条数值一个专属 accent 色，低于阈值条身脉冲动画
- 动作按钮三要素：图标 + 体力消耗/倒计时文案 + CD 进度填充；倒计时数据源必须是服务端（`cooldowns` 剩余秒），客户端只做递减显示
- 监护人/伙伴卡常驻：昵称 + 槽位 + 体力 mini 条 + 在线点 + 贡献次数——共养类页面的"对方在场感"是核心体验
- 实时反馈分层：自己的动作走 HTTP 响应立即反馈；对方动作走 WS 帧（act.* 动画 + toast + typing 提示"对方正在…"+ 流水实时插入）
- 桌面端 = 主列（≤480px 居中）+ 侧栏（对方状态/邀请码/实时流水）；移动端单列
- 舞台渲染挂点表驱动：装饰槽位（bg/back/body/head/hand）按 Z 序分层绘制，换装只换映射不重建节点

**常见坑（S4 核对）**
- [ ] 服装/装饰绘制超出圆形/圆润的身体轮廓（方衣服贴圆身体）——body 槽位必须裁剪到本体形状内，衣料不得伸出轮廓
- [ ] 头部装饰锚点低于眼线，遮住五官——head 锚点必须在眼线之上（头顶）
- [ ] 对方动作后本端 CD 不联动（patch 帧不含 cooldowns）——按 act.* 帧 + 契约 CD 时长本地推算（仅显示层）
- [ ] 数值插值基准与服务端快照混淆——本地插值仅用于显示，任何写返回后必须整体覆盖
- [ ] 嵌入环境/后台标签 rAF 不触发导致舞台黑屏——帧循环需带看门狗兜底（400ms 未触发落 setTimeout）
