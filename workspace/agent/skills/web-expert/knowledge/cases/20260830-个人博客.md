## 问题与根因

1. W1 scrollspy 顶部失效 → 根因：IO 观察带方案天然无法命中"页面顶部无区块"状态，设计时只考虑了"滚动到某区块"，没考虑"回到顶部"这个状态。
2. W4 scrollWidth 溢出 → 根因：装饰性绝对定位元素（光斑）与 `innerWidth`/`clientWidth` 混用，只靠 `body overflow-x:hidden` 兜底而非从源头裁剪。
3. 走查中 clip 截图按文档坐标取景，误判过一次进度条 → 根因：对截图 API 的坐标系假设未验证。

## 三个反思问题（S5 必答）

1. **spec 中哪条验收标准最有效/最没用？**
   最有效：F9"动效仅 transform/opacity + reduced-motion 禁用"——它把性能纪律前置到了写代码之前。最没用：F4"计数 ≤2s"这类纯数值约束，走查时没有实际意义（目检无法量测，实际也无碍）。
2. **偏移日志里的需求为何当初没进 spec？**
   两次偏移都是"边界行为的另一半"：spec 写了"卡片链接占位"却没写"整卡是否可点"；写了"reduced-motion 禁用动画"却没写"跑马灯禁用后内容如何保持可读"。根因：验收标准习惯性只写"正常路径的状态"。改进：spec 模板的"边界与异常"一节应强制对每个动效/交互问一句"禁用/降级时是什么样"。
3. **本项目出现了哪个可复用模式或反模式？**
   模式：ScrollSpyNav 的"滚动位置计算法"优于 IO 观察带法（能表达"顶部"状态）；StarField 的 clientWidth 取值范式。反模式：用 overflow hidden 兜底横向溢出而不裁源头——这次两个溢出源都是这么漏掉的。
