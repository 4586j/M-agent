# ADR-002：设计阶段强制"调研先行"（P11）并新增调研笔记积累池

- 日期：2026-08-30
- 状态：accepted

## 背景

用户在博客项目启动时补充工作流思路："在设计方案时也要上网搜索一下"。v1.1 流程中调研只是 S0 的可选动作（对照 cases/ 找相似经验），没有制度化为卡点检查项，调研发现也没有专门的积累位置——容易每次从零检索、发现散落在对话里丢失。

## 决策

1. 宪法新增 **P11 调研先行**：S0/S1/S2 产出前必须完成外部调研（竞品案例、设计模式、动效/视觉参考），并落盘调研笔记。
2. 新增积累池 `knowledge/research/`（TEMPLATE.md：检索记录 → 发现与来源 → 对本项目的应用 → 模式沉淀评估）。
3. 卡点同步收紧：G1 增加"调研笔记已落盘且 spec 引用至少 3 条要点"；G2 增加"原型参考真实案例"。
4. AGENTS.md 标准动作加入"设计阶段先调研"，积累规则加入调研笔记回写行。

## 备选方案（为什么没选）

- **只改提示词模板，不动宪法**：约束力弱，AI 可跳过；调研笔记的复利价值依赖强制落盘。放弃。
- **调研放在独立阶段（S0.5）**：调研天然贯穿 S0~S2 三个设计阶段（需求找模式、原型找实例、视觉找参考），拆成独立阶段反而割裂。放弃。

## 后果

- 正面：每个设计决策可追溯到外部证据；调研笔记跨项目复用，检索成本递减；与 P4"验证内建"形成"设计有依据、实现有验证"的对称。
- 代价：设计阶段增加 2~5 分钟检索开销；小任务（如组件微调）不适用，P11 仅约束"设计方案"产出。
- 影响范围：constitution v1.1、pipeline v1.2、gates v1.2、AGENTS.md、README；博客项目为首个执行 P11 的项目。
