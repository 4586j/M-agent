# ADR-005：每个项目产物目录初始化独立 Git 仓库

- 日期：2026-09-01
- 状态：accepted

## 背景

项目产物此前只存在于 `output/<项目>/`（如 `output/blog`、后端侧 `output/blog-backend`），没有版本管理：改动无快照、回滚靠手工备份、多轮迭代（blog 已迭代 F1→F24）无法追溯。用户要求"每个项目产物里面再初始化一个仓库，方便版本管理"。

## 决策

1. **每个项目产物目录 = 一个独立 Git 仓库**：在 `output/<项目名>/` 内 `git init` 并做首次提交。
2. **忽略策略（各仓库自带 .gitignore）**：
   - 大体积二进制不入库：blog 的 `assets/*.flac`、`assets/*.mp3`（共 ~111MB）——音源以 `D:\al\erp\music\downloads\` 为单一事实源，恢复方式写在 .gitignore 注释里；小文本资产（`qingtian-lrc.js`、简历 docx）正常入库。
   - 密钥永不入库：`.env`（SMTP 授权码/API Key/JWT 密钥，宪法 P6）；模板 `.env.example` 入库。
   - 依赖/构建/运行时数据不入库：`node_modules/`、`dist/`、`*.db`、日志。
3. **与父目录的关系**：`D:\agent\web` 本身不是仓库（互不影响）；`D:\agent\back` 是仓库且已整体忽略 `output/`，其内的嵌套仓库独立运作，无需 submodule。
4. **提交身份**：用机器全局配置（4586j / 3383351159@qq.com）。

## 备选方案（为什么没选）

- **父仓库直接管理 output/**（web 侧建大仓库）：产物与工作流资产混在一个历史里，粒度粗、克隆冗余；且 back 侧父仓库已把 output/ 忽略，两边规则会不一致。放弃。
- **git submodule 挂进父仓库**：个人项目规模下维护 submodule 的成本 > 收益。放弃。
- **音频文件 LFS / 入库**：本地仓库无 LFS 服务端；111MB 历史膨胀换不来可变内容。放弃（音源本就有外部单一事实源）。

## 后果

- 正面：每个项目可独立提交/回滚/打标签；后续多轮迭代有迹可循；可以直接推 GitHub/Gitee 私有仓库做远端备份。
- 代价：克隆仓库不含音频音源与 .env，需要按 .gitignore 注释与 .env.example 手工恢复（一次性的、有文档的成本）。
- 影响范围：workflow 惯例——**新项目产出时（S3 开始前）即 init 仓库**；本 ADR 为后续所有项目的默认做法。
