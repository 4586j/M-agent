## 发现与可复用要点

### 1. 照顾循环（care loop）是宠物养成的黄金结构
喂食→清洁→陪玩三个动作对应 hunger/clean/mood 三条衰减数值，UI 必须"数值条在哪、动作按钮就在哪"，且动作结果立刻反馈到数值条与宠物动画上（Decay 系统 + Status bars 是该品类的最小闭环）。宠物数值可视化的经典做法：带图标 + 颜色语义的横向条，低于阈值变警示色。

- 来源：[Reddit r/gamedesign: What is the least you'd expect from a virtual pet "system"?](https://www.reddit.com/r/gamedesign/comments/kwe4jm/what_is_the_least_you'd_expect_from_a_virtual_pet/)
- 来源：[freeCodeCamp Forum: Build a Digital Pet Game](https://forum.freecodecamp.org/t/build-a-digital-pet-game-build-a-digital-pet-game/791608)

### 2. 冷却按钮的 HUD 呈现模式
动作按钮在 CD 期间应呈现"倒计时 + 置灰 + 环形/填充进度"三要素，倒计时结束后恢复并给予可点击反馈；冷却由服务端权威（防作弊），客户端只做体验层倒计时。本项目契约 §2.8 的 `cooldowns`（剩余秒数）正是该模式的服务端数据源。

- 来源：[Envato Tuts+: How to Code HUD Cooldown Bars](https://code.tutsplus.com/how-to-code-hud-cooldown-bars--cms-20983t)

### 3. 宠物伴侣设计的留存心理学
宠物作为"需照料的他者"制造责任感与损失厌恶（Octalysis #135）：UI 要强化"它在等我"的真实感——离线期间数值按真实时间衰减并在回来时如实呈现、对方监护人在线状态可见、双方操作实时互通。这直接对应本契约的"服务端权威惰性结算 + WS 实时广播"两大机制。

- 来源：[Yu-kai Chou: Pet Companion Design（Game Technique #135）](https://yukaichou.com/advanced-gamification/the-pet-companion-design-in-gamification/)

### 4. 引擎现实约束：Cocos Creator 编辑器不可用于本环境（关键发现）
后端 ADR-003 选型 Cocos Creator 3.8.x，但本机未安装编辑器（已核查 Program Files/ProgramData/LocalAppData），且编辑器为 GUI 工具 + 需账号登录激活，AI 无法自主完成工程创建/场景编辑/双端构建（T-27/T-38 的完成定义"编辑器打开无报错/构建面板留档"不可达）。ADR-003 自身的复评触发条件 ①②（微信端放弃 → 评估 Web-first；性能不达标 → 评估 Phaser/PixiJS）为切换留了口。**处理：写 ADR-006 记录偏离，工程改用零依赖单文件 HTML + Canvas 2D（与本仓 ADR-003-single-file-html 同构），后端 `02-架构说明.md` §3.2 的 core/platform/game/ui 分层原样保留。**

### 5. 本仓可复用资产盘点（宪法 P2）
- HubClient（blog `index.html` 搜"博客后端联调层"）：`{code,message,data,trace_id}` 解包、401 自动 refresh 重试一次、离线 4s 快速失败——pet 的 HttpClient 直接同构实现，差异点：Idempotency-Key 头、API 前缀 `/api/pet/v1`。
- RandomChat（搜"F25 随机聊天"）：WS 帧协议客户端（心跳/kicked/4401）——pet 的 SocketClient 同构，差异点：seq 去重、synced 前丢增量、退避重连公式 `min(1000*2^n,30000)+rand(0,500)`。
- Toast / ModalFrame（分子组件）：四态轻提示与单实例模态，直接沿用交互定义。
