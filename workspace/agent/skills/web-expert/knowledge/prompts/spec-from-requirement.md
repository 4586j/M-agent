# 提示词模板：需求 → Spec（S0 入口）

用途：把原始需求规格化为可执行契约（spec）。spec 是约束后续所有 AI 产出的依据（宪法 P3）。
使用方式：复制模板替换占位符。改进时直接改本文件并在变更记录注明。

---

## 模板正文

```text
请在本仓库内按 AGENTS.md 约定工作，任务：把下面的需求规格化为 spec。

【原始需求】
{{用户原话或文档}}

【产出要求】
按以下结构生成 output/{{项目名}}/01-spec.md：
1. 背景与目标：一句话说清为谁解决什么问题
2. 页面类型判断：对照 knowledge/patterns/page-patterns.md，判定属于哪类页面，列出将引用的既有模式
3. 用户故事：作为〈角色〉我要〈能力〉以便〈价值〉，覆盖主要路径
4. 功能清单与验收标准：每条功能附【可测】的验收标准（怎样验证做对了）
5. 非目标：本期不做什么
6. 边界与异常：空态/加载/错误/极端数据的处理预期
7. 开放问题：缺失信息清单，每条给出建议假设（按 XX 推进）或必须等用户回答

【规则】
- 验收标准必须可测：禁止"体验良好""响应及时"这类不可验证表述，改写为可检查的条件
- 关键路径有歧义时：列入开放问题等用户回答，禁止替用户假设关键路径
- 相似经验：查 knowledge/cases/ 中同类页面，把既往教训反映进验收标准
- 每条验收标准旁标注它服务的宪法原则（constitution.md P1~P10）
```
