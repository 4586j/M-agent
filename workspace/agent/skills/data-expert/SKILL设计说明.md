# SKILL.md 设计说明

## 一、文件定位

`SKILL.md` 是 data-expert 技能的**唯一入口定义文件**。它在 JiuwenSwarm 框架中承担三个角色：

1. **Agent 的路由触发器** — 框架根据 frontmatter 中的 `tags` 和 `triggers` 判断用户意图是否匹配此技能
2. **Agent 的行为手册** — Agent 在运行时以 SKILL.md 的内容作为 system prompt，指导其如何调用工具和编排流程
3. **用户的参考文档** — 用户可直接阅读了解能力边界、使用方式和注意事项

---

## 二、Frontmatter 设计

```yaml
---
name: data-expert
version: 1.0.0
description: >
  自动化数据分析专家 Skill。接收用户上传的数据文件...
author: data-expert-team
tags: [data, analysis, visualization, pandas, matplotlib, seaborn, data-quality]
dependencies: [pandas, numpy, matplotlib, seaborn, openpyxl, pyarrow]
allowed_tools: [bash, read_file, write_file, code]
triggers: [分析数据, 数据报告, 数据质量, 生成图表, 统计分析]
---
```

### 各字段说明

| 字段 | 用途 | 设计考量 |
|------|------|----------|
| `name` | 技能唯一标识，框架用此名称加载和调度技能 | 使用 `data-expert` 而非中文，保证跨平台兼容，避免编码问题 |
| `version` | 语义化版本号 | 便于技能仓库管理和依赖解析，遵循 SemVer 规范 |
| `description` | 技能能力的自然语言摘要 | 采用 `>` 折行语法保持可读性，内容覆盖"接收什么 → 做什么 → 产出什么"三个要素，方便 Agent 判断是否匹配用户意图 |
| `tags` | 关键词标签列表 | 用于技能市场的分类检索，同时作为 Agent 意图匹配的辅助信号。覆盖技术栈（pandas/matplotlib）和功能域（data-quality）两类标签 |
| `dependencies` | 运行时依赖清单 | 供环境初始化脚本自动安装，明确区分了核心依赖和可选依赖（openpyxl/pyarrow 仅特定格式需要） |
| `allowed_tools` | 技能允许使用的工具白名单 | 遵循最小权限原则：`bash` 执行命令、`read_file`/`write_file` 文件操作、`code` Python 代码执行。不授予网络访问权限，防止数据泄露 |
| `triggers` | 中文触发短语 | JiuwenSwarm 的路由匹配关键词。选择短而常见的短语，覆盖用户可能的表达方式（"分析数据""生成图表""数据报告"等），提升触发命中率 |

## 三、正文结构设计

正文共 9 个章节，按"认知递进"顺序组织：

### 3.1 概述（§ 概述）

**设计意图**：让读者在 30 秒内理解"这个技能能做什么"和"什么时候用"。

- **核心能力表**：6 项能力用表格浓缩呈现，便于快速扫描
- **适用场景**：用用户常见原话（"帮我分析这份数据"）作为场景描述，降低 Agent 误判率

### 3.2 数据格式支持（§ 数据格式支持）

**设计意图**：明确输入边界，防止 Agent 对不支持的格式产生幻觉。

- 表格包含**扩展名、读取方法、额外依赖**三元组，Agent 可根据依赖是否安装判断可行性
- **大文件警告**单独用 blockquote 突出，标注具体阈值（10MB）和替代方案（chunksize=10000），给 Agent 明确的决策依据

### 3.3 处理流程（§ 处理流程）

**设计意图**：以可视化流程图展示 5 步处理流水线，建立 Agent 对执行顺序的全局认知。

- 每一步标注了**使用的类和方法**（如 `DataLoader.load()`），Agent 可直接映射到具体代码模块
- 清洗和分析步骤展开了**子步骤**（如去重、缺失值填充的策略细节），减少 Agent 的自由发挥空间

### 3.4 使用方式（§ 使用方式）

**设计意图**：覆盖三类使用场景，降低使用门槛。

- **命令行**：给出可直接复制的命令，附带参数表说明
- **Python 模块**：给出导入语句和返回值类型注释，方便程序化集成
- **Agent 调用**：给出对话示例，演示自然语言触发方式

### 3.5 数据质量评分体系（§ 数据质量评分体系）

**设计意图**：解释评分逻辑，让用户理解评分来源并信任结果。

- 三维度的**权重、计算方法、满分值**用表格呈现，透明可验证
- 给出**综合评分公式**，避免歧义
- 等级表增加**"建议操作"列**，将评分从"数字"转化为"行动指引"，提升实用性

### 3.6 输出说明（§ 输出说明）

**设计意图**：明确产出物规范，让用户知道在哪里找结果。

- **报告文件**：路径、命名模板、内容结构三要素
- **图表文件**：三种图表的命名模式，便于程序化引用
- **飞书卡片格式**：给出完整的消息模板，用户可据此自定义

### 3.7 错误处理（§ 错误处理）

**设计意图**：明确边界行为，避免 Agent 在异常场景下做出危险操作。

- 6 种常见异常场景覆盖了输入异常（格式不支持、文件缺失）、数据异常（无数值列、常数列）、配置异常（飞书未配置）、资源异常（大文件）
- 每种场景标注了**系统行为**，Agent 按表行事即可

### 3.8 依赖安装（§ 依赖安装）

**设计意图**：一键可用的安装命令，区分核心与可选。

### 3.9 项目结构 & 注意事项（§ 项目结构、§ 注意事项）

**设计意图**：
- **项目结构**：用 ASCII 树形图展示完整文件布局，标注每个文件的职责，方便定位代码
- **注意事项**：5 条关键提醒，覆盖内存安全、中文支持、无头环境、配置安全、幂等性 —— 均为实际开发中容易踩坑的点

## 四、设计原则总结

| 原则 | 体现 |
|------|------|
| **渐进式信息披露** | 概述（What）→ 流程（How）→ 使用（Usage）→ 评分（Why）→ 输出（Result） |
| **给 Agent 写文档** | 步骤对应类方法、参数标注具体值、异常场景有明确的 fallback 行为 |
| **可执行优于可描述** | 代码示例可直接复制运行，不写"你可以这样调用"而是直接给命令 |
| **透明可验证** | 评分公式、清洗策略全部公开，用户可手工验证 Agent 输出的正确性 |
| **最小权限** | `allowed_tools` 仅开放 4 个必要工具，不包含网络/数据库访问 |
