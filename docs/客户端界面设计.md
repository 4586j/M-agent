## 一、现状盘点（设计起点）

### 1.1 已有资产

| 项 | 现状 |
|---|---|
| 视图 | Dashboard 状态总览 / NodeManage 节点管理 / Command 命令台，react-router 组织 |
| 组件 | TaskDetail(320行，含 SSE 订阅) · WorkerCard · TaskList · StatusBadge · StatBar · **CostPanel** · **ConnectionSettings** |
| 实时 | `sseUrl()` 已接 `/tasks/{id}/events`（SSE），api_key 经查询参数透传 |
| 审批 | `approve/reject` 端点已封装，类型有 `awaiting_approval` 状态与 `ApprovalMeta` |
| 成本 | CostPanel 组件已存在（/stats 的 cost 数据） |

### 1.2 缺口（后端有能力、界面无入口）

1. **记忆系统零 UI**：核心记忆 / 任务上下文 / 经验库 / 程序记忆演化共 13 个端点无任何界面
2. **定时调度零 UI**：schedules 5 个端点（cron 任务创建/启停/手动触发）不可视
3. **异步派发缺入口**：命令台只走同步 /dispatch，长任务（web-expert/back-expert 流程）应走 /dispatch/async + SSE
4. **审计不可见**：安全裁决 JSONL（audit_log）事后无法在面板追溯
5. **审批流体验弱**：awaiting_approval 任务缺醒目的待办呈现与 diff 修订界面
6. **实时覆盖不全**：SSE 只用于单任务详情，列表/节点仍纯轮询
7. **用量碎片**：usage/cache/cost 数据在 TaskRecord.meta 里，无聚合视图

### 1.3 设计原则（从架构推导）

1. **任务生命周期是主线**：编排系统的用户关心"我的任务到哪一步了、卡在哪、花了多少"——一切视图围绕它组织
2. **实时优先，轮询兜底**：EventBus/SSE 基础设施已就绪，新视图一律 SSE-first；SSE 断线自动降级轮询
3. **安全必须可见**：关卡①②裁决、审批待办、审计记录不是后台细节，是一等公民
4. **记忆是资产**：经验/提案/核心记忆是系统的"学习成果"，要能浏览、检索、治理
5. **工具面收敛**：视图控制在 7 个以内（GitHub MCP 90+ 工具烧爆 context 的教训同样适用于 UI 导航）
6. **克制的信息密度**：列表页给扫描效率，详情页给完整上下文；默认折叠，按需展开

## 三、视图详细设计

### 3.1 总览 Dashboard（升级）

定位：**10 秒内回答"系统健康吗？有什么需要我处理的？"**

```
┌ 统计条（StatBar 复用） ────────────────────────────────────────┐
│ worker 3/4 ▏任务 128(运行2/待批1/失败3) ▏今日成本 $1.24 ▏缓存命中 78% │
├───────────────────────────┬────────────────────────────────┤
│ 待办中心（新增，最醒目）        │ 状态分布                        │
│ ┌───────────────────────┐ │  ███████████ done 96           │
│ │ ⏸ 审批 task-a1 待裁决    │ │  ████ running 12              │
│ │   [查看diff] [放行][拒绝] │ │  ██ awaiting_approval 4       │
│ │ ⚠ 失败 task-9f 重试3次尽  │ │  █ failed 9                   │
│ │   [查看错误] [重派]       │ │  ▌lost 2  ▌cancelled 5        │
│ └───────────────────────┘ │  （StatusBadge 配色）            │
├───────────────────────────┴────────────────────────────────┤
│ 最近任务（复用 TaskList，行内 SSE 状态点实时跳动）│ 成本趋势(CostPanel 扩展)│
└────────────────────────────────────────────────────────────┘
```

- **待办中心**：聚合 `awaiting_approval`（端点 `/tasks` 过滤）与重试耗尽的失败任务，行内直接操作（approve/reject/redispatch），是审批流的日常入口
- **缓存命中率**：`(Σ cache_read) / (Σ cache_read + Σ input)`，从 /stats 的聚合或 tasks meta 前端算
- 数据源：`GET /stats`（5s 轮询兜底）+ 各类 SSE 事件增量刷新

### 3.2 任务 Tasks（新视图，从总览拆出）

定位：任务全集的检索与单任务深度追踪。

```
┌ 筛选栏 ────────────────────────────────────────────────────────┐
│ [状态▾] [角色▾] [worker▾] [关键词______] [仅看运行中☐] [时间▾]     │
├───────────────────────────────────────┬────────────────────────┤
│ 任务列表（虚拟滚动）                       │ 详情抽屉（点行展开，40%宽）  │
│ ● task-a1  running  12:03  [web-expert] │ ┌────────────────────┐ │
│ ◐ task-9f   awaiting_approval          │ │ 状态时间线(事件流SSE)   │ │
│   （黄色高亮：待审批）                     │ │ 12:01 派发           │ │
│ ✓ task-8c   done    11:47  $0.031      │ │ 12:01 关卡① pass      │ │
│ ✗ task-7b   failed  11:40  [错误摘要]   │ │ 12:02 worker执行中     │ │
│ …                                      │ │ 12:03 ⏸ 等待人工审批   │ │
│                                        │ ├────────────────────┤ │
│                                        │ │ Prompt / 输出(Markdown)│ │
│                                        │ │ 产物列表[在线预览]      │ │
│                                        │ │ 安全裁决 verdict 卡片   │ │
│                                        │ │ 用量: tokens/turns/成本 │ │
│                                        │ │     缓存读 8.2k(78%)   │ │
│                                        │ │ 操作: 取消/重试/重派/审批│ │
│                                        │ └────────────────────┘ │
└────────────────────────────────────────┴────────────────────────┘
```

- **详情抽屉是本视图核心**：TaskDetail 组件升级迁移至此；SSE 订阅当前选中任务，时间线实时追加事件（EventBus 的 status/callback/done）
- 产物预览沿用 `/proxy/artifact`（文本 Markdown 渲染、图片 base64、超限提示 413）
- 审批场景：`awaiting_approval` 时抽屉顶部置顶黄色审批条——展示 security-guard 裁决理由 + 原指令 diff 修订框（approve 带 prompt= 修订重检，不带=直接放行）

### 3.3 节点 Nodes（NodeManage 增强）

- 保留注册表单/心跳刷新/注销
- 新增：**负载可视化**（running 数/容量）、按 `least_load` 策略的推荐排序标记、worker 能力标签（capabilities）、失联倒计时（45s 心跳窗口的可视化进度条）
- 增加部署引导卡（跨主机时指向《跨主机SDK部署手册》）

### 3.4 命令台 Command（升级）

```
┌────────────────────────────────────────────────────────────────┐
│ 模式: (●)同步阻塞  ( )异步+SSE      角色: executor▾  模型: 自动▾   │
│ ┌ 任务说明 ──────────────────────────────────────────────────┐ │
│ │ [web-expert] 阶段：S0；任务：…                             │ │
│ └───────────────────────────────────────────────────────────┘ │
│ 上下文记忆: ____________  引用历史任务: [task-a1 ×] [+添加]      │
│ [检索相似经验 ↸自动填充]                    [派发] (Ctrl+Enter)  │
├────────────────────────────────────────────────────────────────┤
│ 会话历史（原列表增强）                                             │
│ task-… done $0.031 2m12s [展开] ← 详情抽屉复用 Tasks 视图组件     │
└────────────────────────────────────────────────────────────────┘
```

- **异步模式**：走 `/dispatch/async`，派发即创建 SSE 订阅卡片，终态前显示转圈+阶段事件流水——web-expert/back-expert 长流程任务的正确姿势
- **经验引用**：输入框上方"检索相似经验"调 `/experiences/search`（自动剥离 embedding 的响应），一键把相关经验作为 context_memory 附加
- **引用历史任务**：`context_task_ids` 多选输入（自动补全最近任务 id），续做任务的官方入口
- **顾问**：保留 /recommend（AI 推荐拆解），结果以步骤卡片呈现可一键转派发

## 四、实时性策略（统一规范）

| 场景 | 机制 |
|---|---|
| 单任务详情/审批 | **SSE** `/tasks/{id}/events`（EventSource + api_key 查询参数，已有模式） |
| 任务列表状态点 | 轮询 /tasks 5s 兜底 + 已订阅任务的 SSE 终态事件触发局部刷新 |
| 总览统计 | 轮询 /stats 5s（保持现状，量小） |
| 断线处理 | EventSource 自动重连；连续失败 3 次显示"实时已断开，轮询中"角标 |

原则：**SSE 断了界面照常可用**（轮询数据兜底），实时性是增强而非依赖。

## 五、视觉规范（已定稿：生机绿白视觉系统 v1.0）

> 定稿来源：用户提供的《生机绿白视觉系统》设计说明 + 效果图 + 可交互 HTML 原型
> （`web/design/prototype-mint-v1.html`，510 行，Tailwind CDN 可直接打开预览）。
> 设计基调：打破后台"冷灰/纯黑"的机械感，以薄荷绿（Mint）/新生芽绿（Sprout）/柔鼠尾草绿
> （Sage）为生机主基调，大面积纯净白底 + 微渐变，营造呼吸感与现代活力。

### 5.1 Design Tokens（单一事实源，对齐 web-expert P1）

| 语义 | Token / 值 | 界面应用 |
|---|---|---|
| 画布底色 Canvas | `#F4FBF7 ~ #F8FCFA` 极浅嫩草绿微渐变 | 页面背景，通透柔和 |
| 容器卡片 Surface | `#FFFFFF` + 绿调漫反射阴影 `0 8px 24px rgba(16,185,129,0.05)` | 悬浮卡片、抽屉、对话框 |
| 活力主品牌 Primary | `#10B981`（Emerald）/ `#059669` | 导航激活、主派发按钮、完成高亮、健康指示 |
| 嫩绿点缀 Accent | `#34D399 ~ #6EE7B7`（Fresh Mint） | 进度条发光、实时脉冲波纹、标签背景 |
| 待办/审批警戒 Warning | `#F59E0B`（Amber）+ 淡柠绿辅助 | awaiting_approval 待裁决、黄色风险高亮 |
| 错误/阻断 Danger | `#EF4444`（Rose） | 阻断、重试耗尽 |
| 文本层级 | 正文 `#0F172A` / 次级 `#475569` / 辅助 `#94A3B8` | 高清晰度易读深灰文本 |
| 间距/圆角 | 卡片 16px padding · 16px 大圆角（命令台输入区）/ 8px（常规） | 统一卡片节奏 |

状态色语义保持全局唯一：done/pass=Emerald、running/pending=Sky、awaiting_approval/warn=Amber、
failed/block=Rose（StatusBadge 单点维护，禁止同色异义）。

### 5.2 关键组件视觉规格（原型已验证）

- **顶部导航**：56px 玻璃拟态（`rgba(255,255,255,0.85)` + `backdrop-blur-md`），底部 1px 浅绿边线；
  品牌 Logo 为嫩芽几何晶体；7 视图导航带**滑动玻璃指示块**（glass pill，弹性缓动曲线
  `cubic-bezier(0.34,1.45,0.7,1)`）；右侧 `[🟢 SSE已连接]` 翡翠绿呼吸脉冲点 + 实时 ping。
- **统计条**：4 张纯白圆角卡片，顶部细嫩绿渐变边条，hover 微上浮（`-translate-y-0.5`）。
- **待办中心**：淡薄荷渐变包裹的视觉第一焦点，审批卡内联 [查看 Diff][放行][拒绝]。
- **任务抽屉**：右侧 40% 宽，SSE 时间线为贯穿生机绿垂直轴（事件到达淡绿微光展开），
  审批修订条置顶（Amber 底 + Prompt 修订 textarea + 修订放行/拒绝）。
- **演化提案 Diff**：原内容微浅红 / 修订内容淡薄荷绿左右并排，[投 Pass] 绿 / [投 Block] 红。
- **命令台**：同步/异步模式切换 + "检索相似经验"一键填充；派发按钮饱满翡翠绿微渐变。

### 5.3 实现注记（原型 → React 工程）

1. 原型用 Tailwind CDN（演示用）；工程化时将 `mint` 色阶与 `shadow-mint-*` 移入
   `web/tailwind.config.js` theme.extend，业务代码只用语义 token 不写裸色值
2. 原型中 alert/confirm 交互替换为真实 API 调用（approve/reject 已在 client.ts 封装）
3. 原型未覆盖的模块（记忆四 Tab 内容、调度表、审计表、ConnectionSettings）按本文档
   第三节线框实施；效果图（AI 生成）仅作氛围参考，**以 HTML 原型为权威视觉规格**
4. 无障碍底线（web-expert P6）：Amber 文本一律用 `amber-700/800` 于浅底（对比度 ≥4.5:1），
   Mint-400 只作装饰不作正文色
