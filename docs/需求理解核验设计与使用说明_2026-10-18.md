# 个人单 Agent 理解沟通：使用与边界

日期：2026-10-18。按最新用户要求，本机制仅接入个人单 Agent HTTP/UI，已经从 Brain 多 Agent 编排中移除。旧版本“编排台派发前核验”的说明不再作为当前入口说明。

## 使用方式

1. 启动个人 Agent 服务：`python -m agent_core.service --port 8000`，打开 `/panel`。
2. 填写本次需求，在输入区展开“人机理解沟通（个人单 Agent）”。添加真实的项目实现与执行/验收资料，选择 1–3 份。
3. 点击“申请理解核验”主动开启；也可先点击“分析理解偏差”。分析会核对需求与选定资料，并在可用时附上本次执行的 AI 最终输出。只有有依据的严重偏差才会要求核验，普通疑问或资料不足不会自动认定严重。
4. 每题作答后显示解释、总结、资料原文与版本、相关知识/代码原理。资料没有代码时不能臆测具体项目实现。
5. 继续追问保持当前题。只有用户点击“下一题”“暂时跳过”或返回已有题目才切换；模型不能推进题目或修改评分。
6. 暂时跳过的题须补答；全部回答后点击“完成核验”。至少 80% 且关键题全对才满足已触发需求的执行条件，原答案不可覆盖。
7. 对 AI 的错误理解，可以提交纠正内容与知识库原文。待核实意见不用于后续分析，用户核对原文后才作为参考；不修改基础模型参数、不自动写入项目记忆。
8. “学习历史与核查”可回看题目、继续讨论及导出 JSON。中途导出不公开未答题的答案键；全部完成后可导出完整证据。

普通请求没有触发时不要求答题。模型分析仅覆盖显式选定资料和提供的分析文本，不等同于扫描全部代码或保证没有幻觉。CLI 和外部 MCP 本次没有增加这套交互入口。

## 隔离、费用与准入

- 独立出题、追问和偏差分析使用新 SDK 客户端、临时目录，无工具、MCP、项目记忆或执行会话续接。
- 输入 JSON 上限 14,000 字符；单次追问 1,500 字符；本题历史至多 6 组完整问答和 8,000 字符。只按完整轮次淘汰模型历史，审计仍保留原始过程。
- 每题反馈只有该题回答后公开；不同题目的讨论不混合，题目推进使用服务器当前题和事件版本检查。
- 每份资料使用前 3,000 字符出题，完整正文和标题 hash 绑定证据；本次需求最多 4,000 字符，题目引用必须是资料中的连续原文。
- 个人 HTTP 同步、SSE、异步及长会话消息入口统一检查已触发核验。需求/参数、资料版本、一小时有效期和新出现的严重偏差都会在准入时检查。
- 数据位于 `<AGENT_WORK_DIR>/.understanding/<workspace-hash>/`：独立 records.sqlite3、documents 和预算账本；不同工作区不会复用核验或资料。旧 Brain 数据库保持原样，不自动迁移。
- 出题、追问、偏差分析分别预占和结算预算，费用未知或进程中断保留预占；评分、切题、跳过、核实参考不额外调用模型。
- 本项目的沟通账本与执行任务费用分开列账；不是整个项目全部执行的统一预算。SDK 估算也不等于 Ark 账单或严格支付硬截止。
- 数据库记录采用追加写保护。共享 Key 与操作者标签不构成团队人员实名身份；团队模式使用其独立授权机制。

```dotenv
AGENT_UNDERSTANDING_ENABLED=1
AGENT_UNDERSTANDING_MAX_COST_USD=0.10
# 本项目沟通累计预算；0 为不限制：
AGENT_UNDERSTANDING_BUDGET_USD=0
```

Brain 不再读取 `ORCH_UNDERSTANDING_*`，多主机执行 Worker 与团队编排不会加载此人机答题门槛。个人服务复用仓库内预算/资料库类，不需要启动或连接 Brain 进程。
