# 系统架构

> 文档类型：当前源码架构；最后核对：2026-10-18。基线：`main / 516ff74` 加当前未提交工作区。未来目标另列，不把设计图当运行事实。

## 1. 总体分层和边界

| 层/子系统 | 主要模块 | 承担的职责 | 当前边界 |
| --- | --- | --- | --- |
| 个人交互 | [cli.py](../agent_core/cli.py)、[service.py](../agent_core/service.py)、[panel](../agent_core/panel) | 人机对话、执行入口、会话、终端和运行回看 | 个人服务主要使用本机访问/共享 Key，不是团队多用户授权 |
| 统一执行内核 | [kernel.py](../agent_core/kernel.py)、[context.py](../agent_core/context.py)、[tools.py](../agent_core/tools.py) | 人设、上下文、技能/MCP、SDK 执行、流式/多轮与守卫 | 被个人入口、旧 Worker、Brain 本地执行和团队受限文件 Runner 复用；团队使用隔离子进程与独立工具配置 |

| 旧调度控制面 | [brain_api.py](../workspace/agent/orchestrator/runtime/brain_api.py)、[brain_routers.py](../workspace/agent/orchestrator/runtime/brain_routers.py) | 注册、派发、审批、预算、任务、会话、记忆、调度和事件 | 主要是任务级执行控制，不能视为完整团队需求管理系统 |
| 调度与执行适配 | [dispatcher.py](../workspace/agent/orchestrator/runtime/dispatcher.py)、[async_dispatcher.py](../workspace/agent/orchestrator/runtime/async_dispatcher.py)、[local_executor_dispatcher.py](../workspace/agent/orchestrator/runtime/local_executor_dispatcher.py) | 本地/远程、同步/异步派发和结果收尾 | 统一准入包裹已装配的派发器，审批不豁免预算 |

| 团队业务层 | [collaboration](../workspace/agent/orchestrator/runtime/collaboration) | 人员/项目、Agent 归属、职责绑定、需求版本、计划依赖、租约、交付验收、审计 | 独立进程、认证、数据目录；真实规划/文件执行须显式配置，计划须人工确认 |

个人服务当前通过 `ensure_runtime_on_path` 复用仓库里的 BudgetStore/KnowledgeStore 等工具库，不需要连接 Brain 进程。这是源码层依赖，不是各子系统已经完全独立打包；公共持久化模块抽取仍为架构待办。

## 2. 关键执行链

### 2.1 个人执行

1. CLI、HTTP 或个人面板接收需求；HTTP 根据接口选择同步、SSE、异步或长会话。
2. 个人 HTTP 检查本工作区/操作者是否已触发理解核验；普通请求未触发时不要求答题。
3. 已触发时验证证明的需求/参数摘要、资料版本、有效期、最终评分和更新的严重偏差。
4. 解析 persona、模型、cwd 和显式/会话上下文，交给 AgentKernel 和 SDK。
5. 返回结果并记录运行、用量、会话；核验记录只关联运行/轮次编号，问答不注入执行上下文。

CLI 与外部 MCP 本次未加入理解沟通交互入口，不能把 HTTP 的准入范围描述为所有内核调用的统一门控。

### 2.2 个人理解沟通

1. 用户选择 1–3 份资料，主动申请，或执行独立偏差分析；严重偏差需要具体原因及有效引用。
2. 出题器使用新 SDK 客户端和临时目录，不开放工具/MCP、不续接项目会话。
3. 模型输出经结构与逐字引用校验；服务器打乱选项，每题只允许首次评分，评分不交给模型自由判断。
4. 回答后展示解释、总结、原文/版本与知识点。讨论只用当前题、已评分答案和本题近期完整问答。
5. 只有显式 next/skip/revisit/finish 操作改变进度；跳过不计作答，全部补答后至少 80% 且关键题全对才通过。
6. 纠正先待核实；用户核对原文后，在同操作者和同文档 hash 下供后续独立分析参考。

资料 JSON/讨论输入分别限 14,000 字符，单次追问 1,500 字符，本题历史最多 6 组/8,000 字符；出题取每份资料前 3,000 字符并绑定完整正文与标题 hash。原始审计不因模型历史裁剪而删除。详细规则见 [个人说明](需求理解核验设计与使用说明_2026-10-18.md)。

### 2.3 Brain/Worker 执行

1. 控制面接收请求，做参数、上下文与安全前置检查；危险操作进入既有审批。
2. 由 [AdmittedDispatcher](../workspace/agent/orchestrator/runtime/dispatch_context.py) 统一执行预算预占和应用层准入；同步/异步、调度、重试使用装配后的派发器。
3. 本地模式交给本地内核，远程模式按角色或 worker_id 选择节点。
4. 旧 Worker 默认 `ORCH_RUNNER=fake`，切换 SDK 并配置模型后才真实执行。Worker 用 task_id 与业务输入摘要持久声明任务；相同请求复用记录，不同输入冲突，容量满拒绝新执行。
5. 回调和查询共同收集结果；条件状态迁移防止重复终态、取消复活和重复记账。
6. 费用报告持久保存后按执行标识幂等结算。结果/费用未知时保留预占、等待核对，不盲目重新执行。

本链路没有逐题理解核验。审批、预算和安全检查依然有效。

### 2.4 团队业务链

目标链路为：人员/项目授权、需求与验收版本确认、职责规划、依赖派发、实例执行、交付确认、集成与提出人验收/退回。

当前已有业务模型、状态机、Outbox、调度、租约、审计、协议测试及显式启用的真实适配器：

- [真实规划服务](../workspace/agent/orchestrator/runtime/collaboration/sdk_planning.py) 先持久化调用意图和预算，生成候选；人工按版本确认后重新校验需求/职责/预算并发布。无效或资料不足候选不派发。
- [协作 Worker](../worker/collaboration_app.py) 支持 `none/fake/sdk`，默认 none；[SdkRunner](../worker/collaboration_runner.py) 按节点本地引用解析 Provider、人设、工作区，校验依赖副本，在新 attempt 目录交付文件。
- [隔离 SDK 桥接](../agent_core/team_sdk.py) 复用 AgentKernel，使用精简子进程环境、显式工具列表和 PreToolUse 文件路径检查，不继承个人记忆、MCP 或团队实例令牌。

实际模型接线已做小型 Ark 纯文本联调；多职责最终签收有模拟 SDK 协议证据，不能替代实际项目验收。首版不开放任意 Shell 和网络，也不宣称 OS 强沙箱。配置、费用和限制见 [接通说明](团队真实规划与执行接通_2026-10-18.md)。

## 3. 数据归属与权威

| 数据 | 当前位置/实现 | 使用约束 |
| --- | --- | --- |
| 个人运行、事件、持久会话 | work_dir 下运行/会话文件，[run_history.py](../agent_core/run_history.py)、个人 service | 主要按服务进程管理；删除会话不等于删除全部运行记录 |
| 可选本地执行日志 | [run_store.py](../agent_core/run_store.py)，`AGENT_DURABLE_JOURNAL_ENABLED` 默认关闭 | 仅显式 rollout 接管对应本地路径，不代表旧 TaskStore 已全量迁移 |
| 个人沟通 | work_dir 下 `.understanding/<workspace-hash>/`，独立 records.sqlite3、documents 与预算账本 | 按工作区隔离，核验/讨论/导航/纠正追加保存；旧 Brain 核验库不自动合并 |
| Brain 任务 | [task_store.py](../workspace/agent/orchestrator/runtime/task_store.py)，JSON 文件与进程内缓存 | 原子替换与条件迁移不等于支持多个 Brain 进程共同写 |
| 编排预算 | [budget_store.py](../workspace/agent/orchestrator/runtime/budget_store.py)，原预算 JSON 旁 SQLite | JSON 一次性导入后 SQLite 为权威；不要修改旧 JSON 试图重置额度 |
| Worker 接收回执 | work_dir 下 `.worker-receipts.sqlite3` | 输入摘要去重、结果持久化和未完成执行核对；工作目录须独占 |
| 会话/记忆/知识/经验 | 各 store 的可配置目录 | 旧控制面默认装配全局 store，不具备团队级租户授权 |
| 团队业务与产物 | 独立 data_dir 下 `metadata.sqlite3`，[database.py](../workspace/agent/orchestrator/runtime/collaboration/database.py) | 当前 schema 为 15，含规划候选/调用意图与估算费用；需求、产物和审计按团队模型保存，备份/恢复按专门流程 |

## 4. 身份、隔离和安全

- 个人与旧控制面主要依赖 API Key/环回访问策略。`X-Operator` 是审计标签，不是实名登录和不可抵赖证明。
- 团队服务使用独立账号、会话和项目角色；Agent、项目职责绑定、运行实例、节点分别建模。
- 前端连接范围包含连接 ID、规范化地址及配置版本；更换地址/密钥会使相关表单、轮询和事件订阅失效。前端隔离不替代后端授权。
- workspace、工具白名单和声明的隔离级别需要与实际运行环境对应；当前命令终端不是完整 PTY/ConPTY，也不能把 SDK 设置直接当作操作系统沙箱。
- 未知外部副作用、执行中断、费用未知应保留待核对状态，不能仅因重启就自动重放。

## 5. 费用和恢复

预算准入、SDK 单次预算、供应商实际账单分开记录。旧编排已有原子预占和持久幂等结算；个人沟通有独立项目账本；团队有独立 BudgetService，真实适配器按微美元记录规划和执行的 SDK 估值、保留未知预占，仍非跨模式统一项目总账，也非供应商账单。

取消 ACK 不证明执行体已退出；保留容量和预算直到能核对结果。Brain 重启恢复查询原执行，不自动 POST 一份新副作用任务。原预算 JSON、新 SQLite、任务与回执需要配套备份，旧快照不能直接作为新账本回滚。

## 6. 当前限制与演进

个人面板和编排前端共用 [standby.js](../agent_core/panel/standby.js) 与 [bloom.js](../agent_core/panel/bloom.js)，React 通过 [StandbyControl](../web/src/components/StandbyControl.tsx) 挂载，个人服务通过限定文件名的 `/agent/panel-assets/{filename}` 提供模块。默认闲置 5 分钟，原生模态顶层遮挡配合 Shadow DOM、底层 inert/aria-hidden、焦点约束及刷新启动遮挡；不读取业务内容，不中断 SSE、轮询、任务或会话。`m-agent:standby` 事件只暂停/恢复两个宿主的装饰粒子动画。localStorage 按 personal/orchestration 保存设置，sessionStorage 按标签保存待机/最后操作时间；设置可同源同步，恢复操作不跨标签广播，也不跟随 Brain 切换重新挂载。详见 [说明](待机动画方案与接入边界_2026-10-18.md)。

原五套候选保留在独立 [设计室](../web/public/standby-lab/index.html)，不会自动修改正式 UI 设置。团队工作台未接入。本功能不是新的身份认证或服务端授权层。

团队真实规划和文件执行按配置启用，仍缺少实际多职责业务验收、受控代码测试、个人到团队的统一授权入口、面向领导的完整里程碑工作台和跨链路成本总账。Brain 多副本、网络文件系统、多项目强沙箱等不在当前验收承诺中。

变更架构时同时更新本文件、[计划](开发计划.md)、[问题台账](问题修复与解决方法.md) 和必要的 [决策记录](templates/架构决策模板.md)。历史图示见 [旧交互图](architecture-overview.html)，其内容不自动随源码更新。
