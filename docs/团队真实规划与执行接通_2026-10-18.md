# 团队真实规划与执行接通

> 文档类型：实现、使用与验证记录；最后核对：2026-10-18。基线为 `516ff74` 加本批工作区；未提交、未部署。

## 1. 职责与验收规则

人负责目标、高层计划、验收标准、预算、监察和关键决定。项目绑定的不同 Agent 承担分析、实现、技术评审等职责；一名成员可拥有多个 Agent。项目成员权限与 Agent 职责分别建模，不把 manager 当成编程职业。

顺序为：冻结需求与验收版本 → AI 分析并生成候选 → 管理者核对职责、依赖、验收映射与预算后确认发布 → 按依赖执行 → 所属成员确认交付 → 管理者验收工作项 → 集成核对 → 需求提出人最终签收或退回。既有集成工作项可由管理者点名授权绑定执行，保留预算和产物关联。

个人模式的逐题理解沟通不进入这条链路。资料不足时规划器返回澄清问题，补充到需求并重新审核；不会要求领导通过代码知识考试，也不把讨论自动改写为冻结需求。

## 2. 实现与数据

| 部分 | 入口 | 行为 |
| --- | --- | --- |
| 真实规划 | [sdk_planning.py](../workspace/agent/orchestrator/runtime/collaboration/sdk_planning.py) | 调用意图、输入摘要、预算先落库；无工具模型返回候选，再校验职责、绑定、依赖、验收与估值 |
| 候选确认 | 团队面板及 planning-proposals API | 模型不能发布；管理者按 expected_version 确认，重新校验需求、绑定、权限与可用预算 |
| 真实执行 | [collaboration_runner.py](../worker/collaboration_runner.py) | 冻结引用解析为节点本地 Provider、工作区与人设版本；拉取并校验上游产物，在独立 attempt 目录执行 |
| 内核桥接 | [team_sdk.py](../agent_core/team_sdk.py) | 独立进程运行 AgentKernel；精简环境、无个人记忆/会话/MCP/子代理、禁止自动故障切换和纠错重跑 |
| 协议与恢复 | 原有 CollaborationWorker/Journal/ExecutionService | 保留摘要、租约、epoch、重复去重、撤权取消与未知副作用对账；不引入新派发旁路 |

schema 从 14 增量升级到 **15**，增加 `planning_proposals`；原有需求、计划、工作项、预算不重建。输入快照受不可变触发器保护。备份清单包含候选记录；首次启动前按原流程备份，旧程序不能直接打开 schema 15。

候选状态：running、pending、clarification、blocked、unknown、rejected、published。pending 不创建可执行工作项、不预占执行总额；确认发布时才原子创建工作项、预占总额并写 Outbox。规划调用本身的费用独立预占和结算。

同一输入已有活动候选时重复调用返回原记录；中断和 unknown 不自动重放。人工对账需要核实原进程已退出并提交费用证据。running 还在正常超时窗口内时禁止对账；时间经过本身不代表已经停止。迟到结果不会覆盖已作出的人工决定。

API 均位于 `/collab/v1`，沿用团队登录、项目角色和写请求 CSRF/Origin 检查：`GET /capabilities` 查询是否配置真实规划；`POST /projects/{pid}/requirements/{rid}/plans` 返回 proposal，确认前 plan 为 null；`GET /projects/{pid}/requirements/{rid}/planning-proposals` 查询候选；`POST /projects/{pid}/requirements/{rid}/planning-proposals/{proposal_id}/decision` 接收 decision、expected_version、reason，人工 reconcile 另需 usage_units。approve、reject、reconcile 只能由项目管理者执行。

面板用职责卡片展示目标、范围、依赖、验收全文和估值。提出人可按澄清另存新修订，显式保留或调整验收标准，之后重新送审；原候选不能批准新需求版本。无效模型数据只显示阻塞原因，不当作可确认工作项渲染。

## 3. 节点配置与启动

先安装根 README 的依赖，包括 `pip install -e ./agent_core`，再将 [示例](../team-sdk.example.json) 复制为根目录 `team-sdk.local.json` 并修改工作区绝对路径。真实文件已加入忽略规则。Provider 只记录 model、HTTPS base_url、auth_token_env，不写真实凭据。通过操作者已有的安全环境配置设置 `TEAM_ARK_AUTH_TOKEN`；团队入口不自动读取个人 `.env`。

三个示例人设为 analyst-v1、developer-v1、reviewer-v1；项目 Agent 绑定中的 persona_version 必须与节点配置一致。workspace_ref、provider_ref 只是引用，模型不能指定任意磁盘路径或凭据。各执行实例还可以缩小绑定的工具清单。

以下服务和调度命令在 `workspace/agent/orchestrator/runtime` 目录执行。需要先完成 bootstrap、账号/项目/成员/Agent/职责绑定和预算设置：

```powershell
python -m collaboration serve --data-dir ./collab-data --port 7400 --origin http://127.0.0.1:7400 --planner-config ../../../../team-sdk.local.json --auto-dispatch
```

HTTP 服务本身不启动定时循环。另一终端在同一目录运行共享相同 data_dir 和配置的调度宿主：

```powershell
python -m collaboration scheduler --data-dir ./collab-data --planner-config ../../../../team-sdk.local.json --auto-dispatch --interval 5
```

需求批准后 Outbox 触发候选生成；人工确认发布后，后续轮次才会自动派发已就绪工作项。也可从团队面板手动生成候选。默认不传配置仍禁用模型，默认 runner 仍为 none。

节点登记、项目绑定的 slot 和一次性 claim token 仍走既有流程。将 `COLLAB_NODE_TOKEN`、`COLLAB_CLAIM_TOKEN` 放在节点环境中；以下在仓库根执行，示例目录已被 `.tmp/` 忽略：

```powershell
python worker/collaboration_app.py claim --base-url http://127.0.0.1:7400/collab/v1 --state-dir .tmp/team-developer --workspace-ref team-project --provider-ref team-ark --allowed-tools Read,Write,Edit --isolation-mode none
python worker/collaboration_app.py serve --base-url http://127.0.0.1:7400/collab/v1 --state-dir .tmp/team-developer --runner sdk --sdk-config team-sdk.local.json --port 8400
```

上面的 isolation_mode=none 只适合测试数据，默认真实数据派发会被拒绝。实际项目应在独立系统账号、容器或 VM 中运行，按真实环境申报并由项目负责人核验。SDK 子进程隔离不等于这些 OS 隔离，不要为了能派发而伪造 attestation。多实例使用各自 state_dir、端口和职责授权；跨主机服务应走 HTTPS。

## 4. 文件、工具与费用

首版支持 Read、Write、Edit、Glob、Grep，工具集取绑定、本地人设和实例声明的交集；没有工具时显式传 `tools=[]`。仅设置 allowed_tools 是自动批准规则，不能用它声明强限制；本实现还设置 tools 和每次调用的 PreToolUse 路径检查。

每次执行在 `workspace_root/project_id/work_item_id/attempt_id` 下新建目录。inputs 放有摘要核验的依赖副本，只读；outputs 放交付文件。禁止访问目录外、隐藏目录、路径穿越及已识别的外部符号链接。不加载个人和旧 Brain 的设置、历史、记忆、自动 MCP 或子代理；只向 SDK 子进程提供选定 Provider 的凭据与必要系统环境。源代码工作区不会被直接覆盖。

产物包括 team-handover.md、team-usage.json、team-files.json 和各文件的服务端安全名称；manifest 保存原相对路径与 SHA-256。上游产物由下游实例使用当前 attempt 的授权接口拉取，而不是任意 URL。文件数量、单文件 8 MiB、总文件 32 MiB 等限制在运行侧检查。

团队真实适配器统一使用 **1 USD = 1,000,000 整数单位**，向上取整。规划和执行的 `max_cost_usd` 是 SDK 估算上限，不保证供应商实际账单硬上限。既有 Fake 预算单位不会自动换算；启用前应核对项目及全局账户的额度口径。

规划费用按 `adjustment / planning:<proposal_id>` 写入既有 global/project/requirement 账本，确认计划后执行估值按 plan 预占，实际 SDK 估值按 attempt 结算。结果或费用未知时不能以零结算；执行器返回 failed 并保留全部执行预占口径，产物标注 unknown，人工核对前不能把它当作实际已花费用。节点本地 `.sdk-result.json` 保留已取得的费用证据，便于上传失败后核查。
