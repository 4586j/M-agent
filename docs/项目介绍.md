# 项目介绍

> 文档类型：当前事实与产品目标；最后核对：2026-10-18。代码基线：`main / b15dff6` 加当前工作区；近期个人沟通和部分 UI 修复尚未提交，不代表已发布。

## 1. 目标

让个人或团队通过 Agent 完成项目工作，同时保留人的决策、预算、监督和验收责任。统一内核负责模型与工具执行，不同协作入口承担不同的人员关系、授权、需求状态和交付流程。

仓库同时包含可运行的个人 Agent、已有真实执行能力的 Brain/Worker，以及协议/业务模型较完整但真实规划与执行仍需接线的团队子系统。

## 2. 三种协作方式

| 方式 | 人的职责 | Agent 的职责 | 当前完成边界 |
| --- | --- | --- | --- |
| 个人单 Agent | 理解、讨论、参与实现与选择、检查结果 | 分析、编码、工具执行、计划、解释与学习辅助 | CLI、HTTP/UI、会话、内核已实现；理解沟通仅接入个人 HTTP/UI |
| 领导监督多 Agent | 目标、高层计划、验收标准、预算、监察和决策 | 多个职责 Agent 完成需求细化、方案、开发、测试、安全与集成 | 调度执行基础已具备；完整自治项目推进仍为目标 |
| 多人团队与个人 Agent | 多位成员拥有个人 Agent，经授权按项目职责协作 | 执行工作项、报告和交付 | 有人员、归属、职责、需求版本、预算与验收；默认 Planner/Runner 未接通真实模型 |

单机/多主机是部署方式，Agent 数量是执行组织方式，都不直接决定人的职责。一台主机也可以运行多 Agent。

团队模型允许一人拥有多个 Agent，不强制“一人只能一个”。详细对照见 [协作模式与差距](协作模式定位与当前架构差距_2026-10-18.md)。

## 3. 当前能力

- **统一内核**：人设、技能、MCP、上下文、单发/流式/多轮、计划与结果校验，由 [AgentKernel](../agent_core/kernel.py) 等模块实现。
- **个人入口**：CLI、HTTP、个人面板、命令终端、持久会话、运行回放和用量；各入口交互功能不完全相同。
- **理解沟通**：主动申请或独立分析发现有依据的严重偏差时开启；逐题讲解、显式推进、跳过补答、纠正核实和独立审计。
- **Brain/Worker**：节点注册、心跳、角色与定点派发、同步/异步、回调与轮询恢复、重试、取消、预算和审批。
- **控制面板**：任务、节点、会话、Provider、预算、记忆、知识、调度、审计；表单和请求按 Brain 连接范围隔离。
- **团队业务基础**：独立账号和项目授权、需求版本、职责绑定、工作项依赖、实例/租约、交付验收、审计和备份。

以上是代码能力。是否启用取决于配置与执行器装配，是否满足业务要求还需相应验收证据。

## 4. 已确认边界与非目标

1. 个人理解沟通不加入 Brain/Worker 或团队派发；多 Agent 保留业务澄清、批准和验收，不要求领导通过代码知识答题。
2. 讨论使用独立上下文。纠正先待核实，采用后供资料版本匹配的独立分析参考，不训练基础模型，不自动写入执行记忆。
3. 个人 Agent 加入团队需要项目授权；当前尚未打通个人面板与团队身份、私有会话和交付流程。
4. SDK 估算、预算准入和供应商账单分别记录；尚无覆盖个人、编排、团队及全部辅助调用的项目总账。
5. 模拟测试、真实模型联调、业务验收、提交和部署分别记录，不能互相替代。
6. 当前不承诺企业 SSO、多 Brain 高可用、自动生产发布或自动解决全部合并冲突。

## 5. 模块与入口

| 入口 | 位置 | 用途 |
| --- | --- | --- |
| 个人 CLI | [cli.py](../agent_core/cli.py)、[兼容入口](../agent_cli.py) | 多轮交互与命令 |
| 个人 HTTP/UI | [service.py](../agent_core/service.py)、[panel](../agent_core/panel) | 个人执行接口和面板，默认 8000 |
| Brain | [brain_api.py](../workspace/agent/orchestrator/runtime/brain_api.py) | 调度控制面，默认 7000 |
| Worker | [worker_api.py](../worker/worker_api.py) | 执行节点，默认 8000，需避免与个人服务端口冲突 |
| 编排前端 | [web](../web) | React/TypeScript 控制面板 |
| 团队服务 | [collaboration](../workspace/agent/orchestrator/runtime/collaboration) | 独立 API/UI，默认 7400 |
| 团队执行实例 | [collaboration_app.py](../worker/collaboration_app.py) | 团队协议执行侧，默认 runner 为 none |

后端主要采用 Python、FastAPI、SQLite 和文件存储，模型执行使用 Claude Agent SDK；编排前端采用 React/TypeScript/Vite，团队面板使用原生 Web 资源。依赖以 [Python 配置](../agent_core/pyproject.toml)、[运行时依赖](../workspace/agent/orchestrator/runtime/requirements.txt) 和 [前端配置](../web/package.json) 为准，不固定本机安装版本。

## 6. 后续重点

接通团队真实规划/执行与交付验收；打通个人 Agent 的项目授权；完善领导工作台；统一逻辑工作项、执行尝试和费用；继续增强持久化、隔离、可观测性与真实业务验收。

优先级和完成条件见 [开发计划](开发计划.md)，已知限制和修复方法见 [问题台账](问题修复与解决方法.md)。本轮文档更新不表示这些目标已经完成。
