## 各目录功能详述

### 1. `.claude/agents/` —— 子 agent 角色定义
框架"三角色"中两个子 agent 的定义文件，大脑通过 Claude Code 的 Agent 工具按 `subagent_type` 派发。
- **executor.md**：执行角色，`model=sonnet`，拥有全部工具（Read/Write/Edit/Bash/Glob/Grep 等），负责完成大脑下发的子任务并产出结果，路径限定在 `workspace/` 下。
- **security-guard.md**：只读安全检验角色，`model=haiku`，**仅** Read/Glob/Grep/WebFetch 四个只读工具，从工具层面物理剥夺其改文件/执行命令/派发子 agent 的能力，返回结构化裁决 `{verdict, reason, matched_rules, suggestion}`。

### 2. `docs/` —— 项目文档
- **使用手册.md**：框架主文档，涵盖架构、两种部署形态、HTTP 接口速查、配置参考、安全检验、测试与故障排查。
- **实验报告.md**：本次实验的背景、功能、系统设计与总结。
- **superpowers/**：按 superpowers 工作流沉淀的设计规格（`specs/`）与分阶段实施计划（`plans/`），记录从单机编排到跨主机再到 Web 面板的演进过程。

### 3. `web/` —— Web 控制面板
Vite + React + TypeScript + TailwindCSS 实现的图形化前端。
- **src/api/client.ts**：统一封装所有后端 HTTP 接口（stats/workers/tasks/dispatch/register 等），相对路径调用，dev 走 vite proxy、prod 同源直连。
- **src/views/**：三大视图。`Dashboard` 状态总览（大脑模式、节点/任务状态分布、节点卡片展开任务详情、产物在线预览、取消/重派）；`NodeManage` 节点管理（注册 worker、刷新心跳、注销）；`Command` 命令台（派发 prompt，带 role/model/上下文记忆，查看结果与历史）。
- **src/hooks/usePolling.ts**：5 秒自动轮询，驱动界面数据刷新。
- **src/types.ts**：TypeScript 类型定义，与 brain_api/worker_api 的数据结构严格对齐。
- **vite.config.ts**：dev 模式将 `/workers`、`/tasks`、`/dispatch` 等 API 路径代理到大脑 7000；prod 模式构建产物由 brain_api 同源托管。

### 4. `worker/` —— V2 worker 主机
可整体拷贝到其他机器部署的执行端。跨主机模式下，大脑把任务派发到这里执行。
- **worker_api.py**：FastAPI 服务，三个接口：`POST /task`（接受任务，异步执行立即返回 accepted）、`GET /task/{id}`（查状态）、`GET /artifact/{id}`（回传产物文件，含防路径穿越校验）。启动时自动注册到大脑并开后台心跳线程。
- **agent_runner.py**：执行体抽象。`FakeAgentRunner` 测试用（不调真实 SDK）；`SdkAgentRunner` 基于 claude-agent-sdk 加载 executor.md 起真实会话，工作目录隔离到 task 子目录，收集 ResultMessage。
- **worker_config.py**：全部配置由环境变量驱动（`ORCH_BRAIN_URL`/`ORCH_WORKER_ID`/`ORCH_WORKER_HOST`/`ORCH_RUNNER`/`ORCH_PERMISSION_MODE` 等），基于 `__file__` 定位路径避免随 cwd 漂移。
- **tests/**：单元测试。

### 5. `workspace/agent/orchestrator/` —— 大脑
框架的编排中枢，包含 skill 定义、运行时、安全规则与记忆存储。
- **SKILL.md**：大脑七阶段工作流（意图澄清→边界探索→prompt 优化→任务拆解→安全关卡①→执行调度→结果审核+安全关卡②）与派发规则、共识记忆流程。
- **runtime/**：V2 大脑运行时（Python/FastAPI），跨主机模式的核心。
  - **brain_api.py**：大脑 HTTP 服务，集中承载 `/register`、`/heartbeat`、`/dispatch`、`/workers`、`/tasks`、`/proxy/artifact`、`/stats`，并可同源托管前端 `web/dist`。
  - **dispatcher.py**：派发抽象。`LocalDispatcher`（V1 单机兼容）与 `RemoteDispatcher`（V2 选 worker→写 pending→POST /task→轮询→产物检验）。
  - **worker_registry.py**：worker 注册表，心跳保活（45s 超时剔除），选择策略 `round_robin`/`least_load`。
  - **task_store.py**：任务持久化，每任务一 JSON，状态机 pending→running→done/failed/lost/cancelled。
  - **security_guard.py**：两层安全检验（确定性规则引擎 + 可选 haiku LLM 增强，异常优雅降级）。
  - **memory_store.py**：记忆访问抽象接口 + 文件实现，便于将来换 Redis/DB。
  - **dispatch_cli.py**：主会话→brain_api 的派发桥（转发到 /dispatch）。
- **security-rules/**：安全规则集。`default.yaml` 框架自带 10 条规则（危险命令/路径越界/注入/密钥泄露/数据外发）；`overrides/user.yaml` 用户定制；`rules.py` 加载与合并。
- **memory/context/**：上下文记忆存储，按 task-id 分目录存单次任务过程信息，临时、任务结束归档清理。

### 6. `workspace/agent/skills/data-expert/` —— 数据专家技能
executor 可调用的数据分析能力（executor.md 中声明）。提供从数据加载、统计分析、质量评分、可视化到报告生成与飞书发布的完整链路，`run_analysis.py` 为 CLI 入口。该技能体现了框架"加新执行能力即在 skills 下加目录"的扩展点设计。

### 7. 根目录散落文档
- **数据.md / 数据专家Agent开发文档.md / 数据专家Agent项目报告.md**：data-expert 技能的设计、开发与项目说明文档。
- **product-verdict-e2e.png**：产物检验端到端验证截图。

## 逻辑分层小结

从职责看，项目可归纳为四层：

| 层 | 目录 | 职责 |
|----|------|------|
| 编排层 | `workspace/agent/orchestrator/` + `.claude/agents/` | 大脑七阶段工作流、子 agent 定义、安全规则、记忆 |
| 执行层 | `worker/` | 接受任务、执行（Fake/Sdk）、回传产物，可跨主机 |
| 能力层 | `workspace/agent/skills/data-expert/` | executor 可调用的领域技能（数据分析） |
| 交互层 | `web/` | 图形化控制面板，三大视图 + 5s 轮询 |

大脑（编排层）是唯一中枢，执行层与能力层被动接受派发，交互层只与大脑通信（前端统一连 brain，产物经 `/proxy/artifact` 代理）。这一分层使得"单机↔跨主机"仅需切换 `ORCH_MODE`，"加新能力"仅需在 skills 下加目录，扩展性良好。
