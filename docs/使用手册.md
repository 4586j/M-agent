# 多 Agent 编排框架 使用手册

> 三角色（大脑 / executor / security-guard）多 agent 编排框架，支持单机（V1）与跨主机协同（V2）。

---

## 1. 概述

框架由三个角色组成：

| 角色 | 形态 | 职责 |
|------|------|------|
| **大脑 (orchestrator)** | 主会话 skill | 意图澄清、边界探索、prompt 优化、任务拆解、派发、结果审核、共识记忆 |
| **executor** | 子 agent / 远程 worker | 执行任务，产出代码/文件/结论 |
| **security-guard** | 子 agent（本地） | 只读安全检验，返回 pass/block 裁决 |

两种部署形态：
- **单机模式（local，默认）**：大脑在主会话，executor/security-guard 是 Claude Code 子 agent，同进程派发。
- **跨主机模式（remote，V2）**：executor 派发到远程 worker 主机（HTTP + Agent SDK），security-guard 仍留大脑本地。

## 2. 环境准备

### 2.1 依赖安装

```bash
pip install fastapi uvicorn httpx requests pyyaml pytest
pip install claude-agent-sdk   # 仅 worker 真实执行任务时需要
```

### 2.2 关键文件位置

```
.claude/agents/
├── executor.md           # executor 子 agent 定义（model=sonnet，全工具）
└── security-guard.md     # security-guard 定义（model=haiku，只读工具）

workspace/agent/skills/orchestrator/
├── SKILL.md              # 大脑七阶段工作流（主会话加载）
├── security-rules/       # 安全规则（default.yaml + 用户覆盖）
└── runtime/              # V2 大脑运行时（Python）
    ├── brain_api.py      # 大脑 HTTP 服务（注册/心跳/派发）
    ├── dispatch_cli.py   # 主会话↔runtime 桥（CLI 派发入口）
    ├── config.py         # 配置（mode 切换）
    ├── dispatcher.py     # Local/Remote 派发实现
    ├── task_store.py     # 任务持久化
    ├── worker_registry.py# worker 注册/心跳
    └── memory_store.py   # 记忆访问抽象

worker/                   # V2 worker 主机（可部署到其他机器）
├── worker_api.py         # worker HTTP 服务（接受任务/查询/回传文件）
├── agent_runner.py       # Fake/Sdk 执行体
└── worker_config.py      # worker 配置
```

## 3. 单机模式（local，默认）

无需启动任何服务，大脑在主会话直接用 Claude Code 子 agent 派发。

### 使用方式
直接对大脑说话即可，例如「分析 workspace/test.csv」。大脑走七阶段流程，executor/security-guard 作为子 agent 被 Agent 工具派发。

### 切换/确认模式
```bash
# 未设 ORCH_MODE 或设为 local → 单机模式
unset ORCH_MODE          # 确保单机
echo $ORCH_MODE          # 应为空或 local
```

## 4. 跨主机模式（remote，V2）

### 4.1 架构

```
大脑主机                          worker 主机（可多台）
┌─────────────────────┐          ┌──────────────────┐
│ 主会话 (skill)       │          │ worker_api        │
│   │ Bash 调          │          │  /task /task/{id} │
│   ▼                  │  HTTP    │  /artifact/{id}   │
│ dispatch_cli ──HTTP──┼─────────▶│                  │
│   │                  │          │ AgentRunner       │
│   ▼ HTTP             │          │  Fake / Sdk       │
│ brain_api            │◀─HTTP───│  (claude-agent-sdk)│
│  /register /heartbeat│ 注册+心跳 │                  │
│  /dispatch           │─────────▶│                  │
│  /workers /tasks     │          │                  │
└─────────────────────┘          └──────────────────┘
```

**关键点**：派发动作在 brain_api 进程内完成（RemoteDispatcher 与 worker 注册状态同进程），dispatch_cli 只是转发到 brain_api 的 `/dispatch` 端点。

### 4.2 启动大脑

终端 1（大脑主机）：
```bash
cd workspace/agent/orchestrator/runtime
export ORCH_MODE=remote
python -m brain_api
```
大脑监听 `http://127.0.0.1:7000`，等待 worker 注册。

### 4.3 启动 worker 并注册

终端 2（worker 主机，可与大脑同机不同端口）：
```bash
cd worker
# Fake 执行体（不调真实 SDK，用于验证链路）
export ORCH_WORKER_ID=worker-A
export ORCH_WORKER_PORT=8001
export ORCH_WORK_DIR=/tmp/wk_a
python -m worker_api
```

终端 3：向大脑注册 worker：
```bash
python -c "import requests; print(requests.post('http://127.0.0.1:7000/register', json={'worker_id':'worker-A','role':'executor','host':'127.0.0.1','port':8001,'capabilities':{}}).json())"
# 输出: {'status': 'registered', 'worker_id': 'worker-A'}
```

> worker 需主动向大脑注册。心跳由 worker 自行定期发送（本版需配合定时调用 `/heartbeat`，或扩展 worker_api 自动心跳）。

### 4.4 派发任务

方式 A — 经 dispatch_cli 桥（主会话实际调用方式）：
```bash
python workspace/agent/orchestrator/runtime/dispatch_cli.py "分析示例数据并报告行数"
# 输出: {"task_id":"task-xxx","status":"done","output":"...","artifacts":[],"error":null}
```

方式 B — 直接调 brain_api：
```bash
python -c "import requests; print(requests.post('http://127.0.0.1:7000/dispatch', json={'prompt':'统计 CSV 行数'}).json())"
```

带上下文记忆与 model 覆盖：
```bash
ORCH_CONTEXT_MEMORY="用户偏好报告含改进建议" \
ORCH_MODEL=sonnet \
python workspace/agent/orchestrator/runtime/dispatch_cli.py "分析销售数据"
```

### 4.5 拉取产物文件

任务产出文件留在 worker 本地，按需拉取（安全关卡②检验代码时用）：
```bash
curl "http://127.0.0.1:8001/artifact/<task_id>?path=<相对路径>"
```

### 4.6 使用真实 SDK 执行（替代 Fake）

启动 worker 时设 `ORCH_RUNNER=sdk`：
```bash
export ORCH_RUNNER=sdk
export ORCH_EXECUTOR_DEF=.claude/agents/executor.md   # executor 角色定义路径
python -m worker_api
```
worker 将用 claude-agent-sdk 起真实 executor 会话执行任务（消耗 API 调用）。

## 5. 配置参考

### 5.1 大脑配置（环境变量）

| 变量 | 默认 | 说明 |
|------|------|------|
| `ORCH_MODE` | `local` | `local` 单机 / `remote` 跨主机 |
| `ORCH_BRAIN_URL` | `http://127.0.0.1:7000` | 大脑地址（dispatch_cli 转发目标） |
| `ORCH_HEARTBEAT_INTERVAL` | `15` | 心跳间隔（秒） |
| `ORCH_HEARTBEAT_TIMEOUT` | `45` | 心跳超时阈值（秒），超时剔除 worker |
| `ORCH_TASK_STORE_DIR` | `workspace/agent/orchestrator/runtime/.tasks` | 任务持久化目录 |

### 5.2 worker 配置

| 变量 | 默认 | 说明 |
|------|------|------|
| `ORCH_BRAIN_URL` | `http://127.0.0.1:7000` | 大脑地址 |
| `ORCH_WORKER_ID` | `worker-local` | worker 标识 |
| `ORCH_WORKER_HOST` | `127.0.0.1` | worker 监听地址 |
| `ORCH_WORKER_PORT` | `8000` | worker 监听端口 |
| `ORCH_RUNNER` | `fake` | `fake` 测试 / `sdk` 真实执行 |
| `ORCH_EXECUTOR_DEF` | `.claude/agents/executor.md` | executor 角色定义路径 |
| `ORCH_WORK_DIR` | `.../.worker_work` | worker 本地工作区 |

## 6. HTTP 接口速查

### 大脑 (brain_api，端口 7000)

| 方法 路径 | 说明 |
|-----------|------|
| `POST /register` | worker 注册，body: `{worker_id, role, host, port, capabilities}` |
| `POST /heartbeat` | worker 心跳，body: `{worker_id, load}` |
| `POST /dispatch` | 派发任务，body: `{prompt, role, context_memory?, model?}` |
| `GET /workers` | 查活动 worker 列表 |
| `GET /tasks?worker_id=` | 查任务（可按 worker 过滤） |

### worker (worker_api，端口 8000+)

| 方法 路径 | 说明 |
|-----------|------|
| `POST /task` | 接受任务，body: `{task_id, prompt, context_memory, model}` |
| `GET /task/{id}` | 查任务状态与结果 |
| `GET /artifact/{id}?path=` | 拉取产出文件（防路径穿越） |

## 7. 安全检验

security-guard 始终在大脑本地（不跨主机），对指令/产物/代码做检验。

### 规则文件
- 默认规则：[security-rules/default.yaml](workspace/agent/skills/orchestrator/security-rules/default.yaml)
- 用户覆盖：[security-rules/overrides/user.yaml](workspace/agent/skills/orchestrator/security-rules/overrides/user.yaml)（同 id 覆盖默认，新 id 追加）

### 检验裁决
```yaml
verdict: pass | block
reason: "命中规则说明"
matched_rules: [R-XX-NN]
suggestion: "block 时的修改建议"
```

### 硬约束
security-guard 返回 `block` 时，大脑**不自行放行**，停给用户三选一：放行 / 修改 / 放弃。

## 9. 故障排查

| 现象 | 排查 |
|------|------|
| dispatch_cli 返回 `无可用 worker` | worker 未注册或已超时。`GET /workers` 确认；启动 worker 并 `POST /register` |
| worker 注册后很快消失 | 心跳超时。确认 worker 活着并定期发 `/heartbeat`；或调大 `ORCH_HEARTBEAT_TIMEOUT` |
| `ORCH_RUNNER=sdk` 任务 failed | executor.md 路径错（`ORCH_EXECUTOR_DEF`）或 SDK 版本不符；查 worker 日志 |
| 派发 status 一直 running | 任务执行中或 worker 卡死；`GET /task/{id}` 轮询，超时可标 lost 重派 |
| ModuleNotFoundError | 在错误目录执行。dispatch_cli 须从项目根执行，或 `cd runtime` 后直接 `python dispatch_cli.py` |

## 10. 扩展点

- **加新执行能力**：在 `workspace/agent/skills/` 下加 skill，executor 自动可调用。
- **加新 agent 角色**：在 `.claude/agents/` 加定义文件。
- **worker 选择策略**：`select_worker` 当前轮询，可扩展按负载（心跳已带 load）。
- **记忆层换共享存储**：`MemoryStore` 接口已抽象，换 Redis/DB 实现即可。
- **多大脑高可用**：WorkerRegistry 与 TaskStore 接口化后可扩展。
