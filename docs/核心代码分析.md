### 1. dispatch 端点 -- 安全关卡① + 派发（[brain_api.py:130](../workspace/agent/orchestrator/runtime/brain_api.py#L130)）

```python
@app.post("/dispatch")
def dispatch(req: DispatchReq):
    if dispatcher is None:
        return {"status": "failed", "error": "dispatcher 未配置（local 模式不提供 /dispatch）"}
    # security-guard 指令检验；force=true 跳过（用于放行 block 指令）
    if not req.force:
        v = security_check(req.prompt, use_llm=cfg.security_llm)
        if v["verdict"] == "block":
            return {"status": "blocked", "verdict": v, "task_id": None, ...}
    try:
        res = dispatcher.dispatch(role=req.role, prompt=req.prompt,
                                  context_memory=req.context_memory, model=req.model)
    except RuntimeError as e:
        return {"status": "failed", "error": str(e)}
    return {"task_id": res.task_id, "status": res.status,
            "output": res.output, "artifacts": res.artifacts, "error": res.error,
            "product_verdict": res.verdict}
```

**作用**：派发的总入口。先做指令安全检验（关卡①），block 则不创建任务直接返回 `status=blocked`；通过后才调用 dispatcher 派发，并把产物裁决 `product_verdict` 一并返回。
**设计**：安全检验前置、block 即拦截，保证危险指令不会到达 worker。
**已知问题**：`force=true` 可跳过检验且无认证，跨主机暴露时任何人可绕过安全（见代码分析报告 P0）。

### 2. RemoteDispatcher.dispatch -- 选 worker + 轮询 + 产物检验（[dispatcher.py:92](../workspace/agent/orchestrator/runtime/dispatcher.py#L92)）

```python
def dispatch(self, role, prompt, context_memory=None, model=None):
    worker = self.registry.select_worker(role, strategy=self.select_strategy)
    if worker is None:
        raise RuntimeError(f"无可用 {role} worker")
    task_id = f"task-{uuid.uuid4().hex[:8]}"
    self.task_store.write(TaskRecord(task_id=task_id, role=role, prompt=prompt,
        worker_id=worker.worker_id, status="pending", ...))
    base = f"http://{worker.host}:{worker.port}"
    body = {"task_id": task_id, "prompt": prompt, "context_memory": context_memory or ""}
    if model: body["model"] = model
    resp = self.http_call("POST", f"{base}/task", json=body)
    if resp.get("status_code") != 200:
        self.task_store.update(task_id, status="failed", error=f"post failed: {resp}")
        return DispatchResult(task_id, "failed", error=f"post failed: {resp}")
    self.task_store.update(task_id, status="running")
    for _ in range(_POLL_MAX):                         # 轮询：每 0.5s 拉一次
        r = self.http_call("GET", f"{base}/task/{task_id}")
        st = r.get("json", {}).get("status")
        if st in ("done", "failed"):
            out = r.get("json", {}).get("output")
            arts = r.get("json", {}).get("artifacts", [])
            verdict = None
            if st == "done" and self.product_check:
                verdict = self._check_product(base, task_id, out, arts)  # 产物检验
            self.task_store.update(task_id, status=st, output=out,
                                   artifacts=arts, error=..., verdict=verdict)
            return DispatchResult(task_id, st, out, arts, ..., verdict)
        time.sleep(0.5)
    self.task_store.update(task_id, status="failed", error="poll timeout")
```

**作用**：选 worker -> 写 pending -> POST 任务到 worker -> 标 running -> 每 0.5s 轮询 `GET /task/{id}` -> 拿到 done/failed 后做产物检验并落盘。
**设计**：任务状态随流程推进（pending->running->done/failed），done 时触发产物检验（关卡②）。
**已知问题**：① `time.sleep` 同步阻塞，占线程最长 500s；② 轮询不检查任务是否已取消；③ 任务绑死单 worker，无自动故障转移（见 P1）。

### 3. _check_product -- 产物检验内容合并（[dispatcher.py:136](../workspace/agent/orchestrator/runtime/dispatcher.py#L136)）

```python
_TEXT_ARTIFACT_EXT = {".md", ".txt", ".py", ".json", ".yaml", ".yml", ".sh",
                      ".ts", ".tsx", ".js", ".jsx", ".csv", ".log", ".ini", ...}

def _check_product(self, base, task_id, output, artifacts):
    combined = output or ""
    for art in artifacts or []:
        if not _is_text_artifact(art):     # 二进制产物跳过，避免拉取巨大/无意义内容
            continue
        try:
            ar = self.http_call("GET", f"{base}/artifact/{task_id}", params={"path": art})
            if ar.get("status_code") == 200:
                combined += f"\n\n--- artifact: {art} ---\n" + ar.get("json", {}).get("content", "")
        except Exception:
            continue
    return self.product_check(combined)
```

**作用**：把任务 output 与所有文本类产物内容拼成一个字符串，过 security-guard 检验。二进制产物跳过。
**设计**：仅检文本、避免拉大文件；产物 block 时任务仍 done 但 verdict 标记，前端显示橙色警告（不混淆 failed）。

### 4. select_worker -- 节点选择策略（[worker_registry.py:56](../workspace/agent/orchestrator/runtime/worker_registry.py#L56)）

```python
def select_worker(self, role="executor", strategy="round_robin"):
    alive = [w for w in self._alive() if w.role == role]   # 先过滤存活
    if not alive:
        return None
    if strategy == "least_load":
        return min(alive, key=lambda w: (w.load, w.last_heartbeat))  # 负载最低
    if role not in self._rr:
        self._rr[role] = itertools.cycle(alive)             # 轮询器
        return next(self._rr[role])
    for _ in range(len(alive)):                             # 轮询但跳过已失联
        cand = next(self._rr[role])
        if cand in alive:
            return cand
    return alive[0]
```

**作用**：两步选 worker -- 先按心跳过滤存活节点，再按策略挑一个。`round_robin` 用 `itertools.cycle` 轮流分配；`least_load` 取负载最低。
**设计**：注册新 worker 时 `self._rr.pop(role)` 重建轮询器，新节点立即纳入；轮询时跳过已失联的。
**已知问题**：worker 心跳上报 `load` 恒为 0，`least_load` 退化为取心跳最新。

### 5. _alive -- 心跳保活剔除（[worker_registry.py:45](../workspace/agent/orchestrator/runtime/worker_registry.py#L45)）

```python
def _alive(self):
    now = self._now()
    return [w for w in self._workers.values()
            if now - w.last_heartbeat <= self.heartbeat_timeout]   # 默认 45s

def heartbeat(self, worker_id, load=0):
    w = self._workers.get(worker_id)
    if w is None:
        return
    w.last_heartbeat = self._now()
    w.load = load
```

**作用**：超过 `heartbeat_timeout`（45s）未发心跳的 worker 不算存活，不会被选中。心跳更新时间戳与 load。
**设计**：被动剔除，无需主动探测；worker 端后台线程每 15s 发一次心跳。
**已知问题**：`_workers` 裸 dict 无锁，并发可能 `dict changed size`（见 P0）。

### 6. TaskRecord -- 任务状态机与持久化（[task_store.py:7](../workspace/agent/orchestrator/runtime/task_store.py#L7)）

```python
VALID_STATUSES = ("pending", "running", "done", "failed", "lost", "cancelled")

@dataclass
class TaskRecord:
    task_id: str; role: str; prompt: str; worker_id: str | None
    status: str; created_at: str; updated_at: str
    output: Any = None; artifacts: list = field(default_factory=list)
    error: Any = None
    verdict: dict | None = None     # security-guard 产物裁决（done 命中规则时存在）

def update(self, task_id, **fields):
    rec = self.get(task_id)
    if rec is None: raise KeyError(f"task not found: {task_id}")
    if "status" in fields and fields["status"] not in VALID_STATUSES:
        raise ValueError(f"invalid status: {fields['status']}")
    for k, v in fields.items():
        setattr(rec, k, v)
    self.write(rec)            # 每个任务一个 JSON 文件
```

**作用**：定义 6 态状态机，每次 update 校验状态合法并落盘 JSON。
**设计**：状态校验防非法流转；每任务一文件便于按 id 查询与人工排查。
**已知问题**：`list_all` 等全量扫描所有 JSON（O(n)），反序列化 `TaskRecord(**json.load)` 无容错（见 P2）。

### 7. security-guard 两层检验与降级（[security_guard.py:41](../workspace/agent/orchestrator/runtime/security_guard.py#L41)）

```python
def check(content):                       # 确定性正则规则引擎
    for r in load_effective_rules():
        if re.search(r["pattern"], content):
            (matched_block if r["severity"] == "block" else matched_warn).append(r)
    if matched_block:  return {"verdict": "block", ...}
    if matched_warn:   return {"verdict": "pass", "reason": "命中 warn（已放行）", ...}
    return {"verdict": "pass", "reason": "无规则命中", ...}

def check_with_llm(content, use_llm=False):
    rule_v = check(content)
    if rule_v["verdict"] == "block":   return rule_v           # 规则 block 直接返回，省 LLM
    if not use_llm:                    return rule_v
    llm_v = _llm_judge(content)                                # 规则 pass 才调 haiku
    if llm_v is None:                  return rule_v           # LLM 不可用 -> 降级规则结果
    if llm_v.get("verdict") == "block":  return {"verdict": "block", "reason": "LLM 判断: ...", ...}
    return rule_v
```

**作用**：第一层正则规则引擎（block/warn 两级），第二层可选 LLM（haiku 只读会话）补判"规则之外"可疑情况。
**设计**：规则 block 直接返回省 LLM 调用；LLM 不可用/异常时 `graceful` 降级到规则结果，不阻塞主流程。这是框架安全设计的精华。

## 二、worker 执行端

### 8. post_task -- 异步执行立即返回（[worker_api.py:84](../worker/worker_api.py#L84)）

```python
@app.post("/task")
def post_task(body: TaskBody):
    with lock:
        state[body.task_id] = TaskResult(body.task_id, "running")   # 先占位 running 供 brain 轮询
    def _bg():
        try:
            _execute(body)                    # 后台线程跑 runner
        except Exception as e:
            with lock:
                state[body.task_id] = TaskResult(body.task_id, "failed",
                                                 error=f"execute error: {e}")
    threading.Thread(target=_bg, daemon=True, name=f"task-{body.task_id}").start()
    return {"task_id": body.task_id, "status": "accepted"}
```

**作用**：收到任务后立即返回 `accepted`，实际执行放后台线程；state 先占位 `running` 让大脑轮询可见，完成或异常时覆盖。
**设计**：异步避免长任务阻塞 HTTP 连接；`threading.Lock` 保护 state；异常兜底标 failed。
**已知问题**：state 字典随任务累积无清理（内存泄漏）；线程 `daemon=True`，worker 崩溃则任务丢失。

### 9. start_auto_heartbeat -- 启动即注册 + 定期心跳（[worker_api.py:38](../worker/worker_api.py#L38)）

```python
def start_auto_heartbeat(cfg, interval=None, stop_event=None, http_post=None):
    interval = interval or cfg.heartbeat_interval
    stop_event = stop_event or threading.Event()
    def loop():
        post = http_post or requests.post
        register_to_brain(cfg, http_post=post)             # 先注册（失败重试 3 次）
        hb_url = f"{cfg.brain_url}/heartbeat"
        while not stop_event.is_set():
            try:
                post(hb_url, json={"worker_id": cfg.worker_id, "load": 0}, timeout=5)
            except Exception:
                pass
            stop_event.wait(interval)                       # 每 15s 一次
    t = threading.Thread(target=loop, daemon=True, name="worker-heartbeat")
    t.start()
    return t
```

**作用**：worker 启动时开后台线程：先向大脑注册，再按 interval 周期发心跳。daemon 随主进程退出。
**设计**：注册+心跳合一，`ORCH_AUTO_REGISTER=1`（默认）时自动启用，零配置接入大脑。
**已知问题**：注册只在启动时发一次，大脑重启后 worker 需重启重注册；心跳 `load` 恒 0；异常静默 `pass`。

### 11. SdkAgentRunner.run -- 真实 SDK 执行（[agent_runner.py:83](../worker/agent_runner.py#L83)）

```python
def run(self, req: TaskRequest) -> TaskResult:
    import claude_agent_sdk as sdk
    meta = self._parse_executor_def()              # 解析 executor.md frontmatter
    task_dir = self.work_dir / req.task_id          # 工作目录隔离到 task 子目录
    task_dir.mkdir(parents=True, exist_ok=True)
    options = sdk.ClaudeAgentOptions(
        cwd=str(task_dir),
        model=req.model or meta["model"],           # 派发 model 优先，否则 executor.md 的 sonnet
        system_prompt=meta["prompt"],
        permission_mode=self.permission_mode,       # bypassPermissions / acceptEdits / default
        max_turns=50,
    )
    if meta["tools"]:
        options.allowed_tools = [t.strip() for t in meta["tools"].split(",")]
    async def _run():
        outputs = []
        async for msg in sdk.query(prompt=full_prompt, options=options):
            if isinstance(msg, sdk.ResultMessage):
                outputs.append(msg.result or "")
        return "\n".join(outputs)
    output = asyncio.run(_run())
    artifacts = [str(p.relative_to(task_dir)) for p in task_dir.rglob("*") if p.is_file()]
    return TaskResult(req.task_id, "done", output=output or "(无输出)",
                      artifacts=artifacts, error=None)
```

**作用**：加载 executor.md 定义，用 claude-agent-sdk 起 executor 会话执行任务，工作目录隔离到 `work_dir/{task_id}/`，收集 `ResultMessage` 作为输出，目录下所有文件作为产物。
**设计**：cwd 隔离避免任务间互相污染；产物自动 rglob 收集；model 可派发覆盖。
**已知问题**：`asyncio.run` 在线程（当前能跑但脆弱）；`max_turns=50` 只限轮数不限总时长，无超时。

## 三、前端控制面板

### 12. usePolling -- ref 持最新回调防闭包陈旧（[hooks/usePolling.ts](../web/src/hooks/usePolling.ts)）

```typescript
export function usePolling<T>(fn: () => Promise<T>, ms: number, enabled = true) {
  const [data, setData] = useState<T | null>(null)
  const [loading, setLoading] = useState(true)
  const fnRef = useRef(fn); fnRef.current = fn          // ref 持最新 fn，避免闭包陈旧
  const enabledRef = useRef(enabled); enabledRef.current = enabled
  const aliveRef = useRef(true)                          // 防卸载后仍 setData
  useEffect(() => {
    aliveRef.current = true
    const tick = async () => {
      if (!enabledRef.current) return
      try { setData(await fnRef.current()) }
      catch { /* 忽略，下次轮询重试 */ }
    }
    tick()
    const id = setInterval(tick, ms)
    return () => { aliveRef.current = false; clearInterval(id) }   // 清理
  }, [ms])
  return { data, loading, refresh: tick }
}
```

**作用**：通用轮询 hook，每 ms 调一次 fn 刷新数据。
**设计**：`fnRef`/`enabledRef` 持最新值避免闭包捕获旧 state；`aliveRef` + cleanup 防组件卸载后仍 `setData`。这是前端最值得肯定的健壮性设计。
**已知问题**：`enabled=false` 时 `loading` 永真（见 P2）。

### 13. request\<T\> -- 统一 HTTP 与错误提取（[api/client.ts](../web/src/api/client.ts)）

```typescript
async function request<T>(url: string, init?: RequestInit): Promise<T> {
  const r = await fetch(url, { headers: { 'Content-Type': 'application/json' }, ...init })
  if (!r.ok) {
    let detail = r.statusText
    try {
      const body = await r.json()
      detail = body.detail || body.error || detail     // 统一提取后端错误信息
    } catch { /* 非 JSON 响应 */ }
    throw new Error(`${r.status}: ${detail}`)
  }
  return r.json() as Promise<T>
}

export const api = {
  stats: () => request<Stats>('/stats'),
  workers: () => request<WorkerInfo[]>('/workers'),
  dispatch: (body: DispatchBody) =>
    request<DispatchResult>('/dispatch', { method: 'POST', body: JSON.stringify(body) }),
  artifact: (workerId, taskId, path) =>
    request<{ content: string }>(`/proxy/artifact?worker_id=${...}&task_id=${...}&path=${...}`),
  // ...register/heartbeat/cancelTask/redispatchTask 等
}
```

**作用**：封装所有后端调用，统一处理 HTTP 错误与 JSON 解析，按 `types.ts` 泛型返回。
**设计**：相对路径调用（dev 走 vite proxy、prod 同源）；错误信息兼容 `detail`/`error` 两种后端格式；类型与后端数据结构严格对齐。
**已知问题**：`fetch` 无超时，后端 hang 时请求堆积（见 P2）。

## 小结

13 段核心代码覆盖了框架的关键路径：

| 子系统 | 核心代码 | 设计精华 |
|--------|---------|---------|
| 大脑 | dispatch 关卡前置、RemoteDispatcher 轮询、产物合并检验、选择策略、心跳剔除、状态机、两层安全降级 | 安全检验强制前置 + 规则/LLM 分层降级 |
| worker | 异步执行、自动注册心跳、产物路径防护、SDK 隔离执行 | 异步不阻塞 + 工作目录隔离 |
| 前端 | ref 防闭包轮询、统一错误提取 | 健壮性细节 |

设计层面成熟可圈；工程缺陷集中在产物穿越防护不彻底、同步阻塞轮询、线程安全与无认证（详见 [代码分析报告.md](代码分析报告.md)）。
