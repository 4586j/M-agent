# 多 Brain 会话隔离、开发代理与策略文件修复

日期：2026-10-15。Git 基线：`main`，`b15dff6`。

修复基于工作区已有 UI 改动进行，未提交 Git。

## 修复范围

| 问题 | 修复后的行为 |
| --- | --- |
| 派发页用全局 `orch_dispatch_session_id` 保存选择，切换 Brain 时继续发送旧会话 ID | 按连接 ID 与规范化后的 Brain 地址分别保存；切换回来恢复对应选择，修改连接地址视为新的范围 |
| 旧版全局选择没有归属信息 | 仅在当前 Brain 返回的会话列表包含该 ID 时迁移；不存在的已保存选择会在列表加载后清除 |
| 切换 Brain 后派发表单及异步创建会话响应串入新连接 | 按 Brain 范围重建派发表单，清空草稿、目标、结果与上下文引用；迟到的创建响应不更新已卸载表单或新连接的选择 |
| 节点页跳转携带的 `workerId` 在切换后被重新使用 | 路由状态同时记录所属 Brain；只有归属匹配时才回填节点目标，即使两个 Brain 的节点 ID 相同也不会继承 |
| Vite 开发代理缺少预算、供应商、会话和知识 API，返回前端 HTML | 新增 `/budgets`、`/providers`、`/sessions`、`/knowledge`，同时转发子路径；保留现有 `ORCH_BRAIN_URL` 目标配置 |
| 项目根 `.agent_policy.json` 为 `{ 不是 JSON` | 保留损坏文件备份，恢复合法的默认边界策略；启用边界及命令路径扫描，逐次确认，无额外放行目录 |
| 策略测试直接改写真实配置，进程中断可能留下测试内容 | 将所有策略用例切换到临时项目根与独立策略缓存，测试不再写开发机配置 |

切换 Brain 会清空尚未发送的派发草稿；会话历史仍在所属 Brain 的后端保存。这次调整的是前端选择、派发表单及请求归属，不涉及跨 Brain 搬迁后端会话。
