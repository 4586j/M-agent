# 技术栈、运行环境与启动方式

按 2026-10-06 的仓库现状与本机实测整理。命令与默认值都取自源码（`argparse` 定义、`AppConfig`、CI 工作流），不是设想；未部署、未验证的部分在第 12 节明确写出。

## 1. 一个仓库，两套互不导入的运行时

| 运行时 | 位置 | 说明 |
| --- | --- | --- |
| 旧编排栈 | `agent_core/`、`workspace/agent/orchestrator/runtime/`（brain）、`worker/worker_api.py`、`web/` | 单机 CLI / 本地服务 / 集群 brain + worker + 控制面板，见 `README.md` 与 `docs/使用手册.md` |
| 协作服务 | `workspace/agent/orchestrator/runtime/collaboration/`（服务 + 面板静态资源）、`worker/collaboration_*.py`（执行实例） | 多人多项目的需求→审批→拆解→派发→交付闭环，见 `docs/团队协作功能开发文档.md` |

协作模块不导入 `worker_api` / `agent_runner` / `agent_core`，也不共享旧数据文件；这条边界由用例钉住：`tests/test_collaboration_app.py::test_import_has_no_database_or_dotenv_side_effects` 在导入 `collaboration.app` 与 `collaboration.__main__` 时禁止 `sqlite3.connect`、禁止读取 `.env`，并断言 `brain_api` 未被导入。旧启动链因此可以单独存在，协作服务也可以整块停用。

## 4. 配置与密钥

- 模板是根目录 `.env.example`，复制为 `.env` 使用；`.env` 已被 `.gitignore` 忽略，密钥不入库。
- 已存在的真实环境变量优先级高于 `.env`；换文件名或位置用 `AGENT_ENV_FILE=/path/to/your.env`。
- 变量分两套前缀：`AGENT_*`（内核 CLI/服务）、`ORCH_*`（brain、worker、安全门、存储目录）；`ANTHROPIC_*` 为 SDK 鉴权与模型选择。全部含义见 `docs/使用手册.md`。
- 协作服务**不读 `.env`、不读任何 `ORCH_*`/`AGENT_*` 变量**：它的全部配置来自命令行（`--data-dir` / `--host` / `--port` / `--origin`）与 `AppConfig` 默认值。执行实例侧只有三个环境变量：`COLLAB_NODE_TOKEN` 与 `COLLAB_CLAIM_TOKEN`（claim 阶段读入，可由 `--node-token-env` / `--claim-token-env` 改名），以及 `COLLAB_INSTANCE_TOKEN`（serve 阶段优先于 state 目录里的令牌文件读取，好让密钥不必落盘）。
- 测试不依赖也不写入个人 `.env` 与真实模型凭证：真进程用例在子进程环境里剥掉 `AGENT_*`/`ORCH_*`/`ANTHROPIC_*`/`OPENAI_*`，并把 `AGENT_ENV_FILE` 指向不存在的文件。

## 6. 启动：协作服务

数据目录不需要事先存在：第一条命令（通常是 `bootstrap`）会把目录和 `metadata.sqlite3` 一起建出来。库里只有一个文件装的就是全部持久事实——需求原文、交付产物字节与审计流水都在这一个 SQLite 文件内（产物是 BLOB），所以一次在线复制就是整份档案，也意味着这个文件是全部原文的完整副本。

```bash
cd workspace/agent/orchestrator/runtime

# ① 建第一个管理员（交互式两次读口令，12–1024 字符；只写本地库，不联网）
python -m collaboration bootstrap --data-dir DIR --username admin --display-name 管理员

# ② 起服务：默认 127.0.0.1:7400，API 前缀 /collab/v1，面板在 /ui
python -m collaboration serve --data-dir DIR --host 127.0.0.1 --port 7400 \
       --origin http://127.0.0.1:7400

# ③ 登记一台执行节点（一次性打印 node_id 与 node token，服务端只存摘要）
python -m collaboration node-enroll --data-dir DIR --name box-a
python -m collaboration node-disable --data-dir DIR --node-id NODE_ID   # 级联禁用该节点活实例

# ④ 常驻调度宿主（独立进程，Ctrl-C 干净退出；默认不自动派发）
python -m collaboration scheduler --data-dir DIR --interval 5 [--iterations N] \
       [--project PROJECT_ID] [--auto-dispatch]

# ⑤ 备份与恢复围栏（第 15.2 / 15.3 节，见 18.44 与 18.45）
python -m collaboration backup --data-dir DIR --out ARCHIVE.sqlite3      # 复制后回读验证，写清单
python -m collaboration restore-fence --data-dir DIR                     # 把档案里的授权一律作废
```

需要知道的约束（都是代码里的闸门，不是建议）：

- `--origin` 以 `http://` 开头时**必须绑回环**，否则拒绝启动；非回环需要 HTTPS origin。
- `serve` 关闭 `/docs` 与 `/openapi.json`；所有响应 `cache-control: no-store`。
- `AppConfig` 默认 `session_ttl=28800`（60–86400）、`lease_ttl=120`（30–86400）、`auto_dispatch=False`。
- `scheduler --interval` 限 0.1–3600 秒，`--iterations` 至少 1。
- `backup` 拒绝覆盖已存在的档案或清单，也不接受目标目录里残留的 `.part`；清单为 `<out>.manifest.json`，只含 schema 版本、字节数、sha256、逐表计数与校验结果，不含原文、姓名或令牌。
- `restore-fence` 只写它被 `--data-dir` 指到的那个目录：禁用所有活跃节点及其实例（每实例抬一次 `control_epoch`）、把所有未撤销会话置为已撤销，不改任何尝试行，也不判定任何一轮。
- 令牌与口令一律只存摘要；`node token` / `instance token` / `claim token` 只在签发那一次以明文出现。

## 7. 启动：协作执行实例（Worker）

```bash
cd worker

# ⓪ 先由项目侧开出这一格：面板上或
#    POST /collab/v1/projects/{pid}/agent-bindings/{bid}/instances {"node_id": ..., "worker_url": ...}
#    返回 instance_id 与一次性的 claim_token
# ① 用第 6 节 ③ 打印的 node token 与上面那个 claim token 认领执行实例（凭据都从环境变量读）
COLLAB_NODE_TOKEN=... COLLAB_CLAIM_TOKEN=... \
python collaboration_app.py claim --base-url http://127.0.0.1:7400 --state-dir DIR \
       --workspace-ref workspace-a --provider-ref provider-a \
       --allowed-tools Read,Edit --env-allowlist "" --isolation-mode none \
       --isolation-attestation "" --capacity 1

# ② 起这台实例的 HTTP 入口（默认 127.0.0.1:8400，唤醒路径 /wake）
python collaboration_app.py serve --base-url http://127.0.0.1:7400 --state-dir DIR \
       --host 127.0.0.1 --port 8400 --runner fake --lease-interval 30 --poll-interval 30
```

- 默认只允许绑回环；非回环必须显式 `--allow-remote`。
- `serve` 需要的实例令牌：`claim` 成功后写进 `--state-dir`，或放在 `COLLAB_INSTANCE_TOKEN` 里（环境变量优先，好处是密钥不落盘）。
- `--runner` 只有 `none` 与 `fake` 两个取值：**没有接真实模型**，`fake` 产出的产物里逐字写着 `simulated: true`，`serve` 状态里也回报 `simulated`。
- 这个入口不触碰旧 worker 的 `/task`、面板、终端与全局工作区；唤醒提示只当作「该看一眼」的信号，行动前一定重新拉取，摘要 / epoch / 租约都以服务端返回值为准。

## 9. 测试与质量门

```bash
# 全仓确定性回归（不触网、不需 API key；本文各节记录的通过数都来自这条）
python -m pytest agent_core/tests worker/tests workspace/agent/orchestrator/runtime/tests \
       eval/tests -q --tb=short -m "not sdk_smoke"

# 只看协作 runtime 目录
cd workspace/agent/orchestrator/runtime && python -m pytest tests -q

# 真实 SDK 冒烟（需要 ANTHROPIC_API_KEY，会产生模型费用——单独确认后再跑）
python -m pytest agent_core/tests -q -m sdk_smoke

# 前端：单测 / 构建 / 两套浏览器用例（在 web 目录内执行）
npm --prefix web test && npm --prefix web run build
cd web && node node_modules/@playwright/test/cli.js test --config=playwright.config.js
cd web && node node_modules/@playwright/test/cli.js test --config=playwright.orchest.config.js

# 静态检查（增量门：新增/改动处零告警，存量不强求全绿；line-length 100，规则集 E9/F/B/I）
ruff check <改动文件>

# 评测（dry-run 不连 brain、不执行模型）
python eval/run_eval.py --dry-run
```

跑测试前要知道的三件事：

1. 不要同时跑两套 pytest：真进程用例自己占端口、自己派生子进程，并行会互相踩。
2. 跑全量之前先收干净一次性 `python -m collaboration serve` 进程，否则真进程 e2e 会超时并报出假 flake。
3. 一次性实验目录用仓库根的 `.tmp/`；它**没有**被 `.gitignore` 忽略，所以提交只按文件名 `git add`，用完删掉该目录。

## 10. CI 概览（现状描述，本轮未改动 CI）

`.github/workflows/ci.yml` 实际会跑的作业：`python-tests`（Ubuntu，3.11/3.13 矩阵）、`windows-tests`（Windows，3.11/3.13 矩阵，专测进程树与路径假设）、`clean-package`（全新虚拟环境安装 + 导入冒烟）、`eval-smoke`（任务集 dry-run + `eval/tests` 纯逻辑，不触网）、`frontend`（Vitest + 构建，硬门禁）。

另有两格是**写好但关掉**的占位：`eval-real`（真实 brain 派发评测）与 `sdk-smoke`（`python -m pytest agent_core/tests -q -m sdk_smoke`）都带 `if: false`，等 API key 与评测环境就绪后移除该条件才启用。所以第 9 节那条 `sdk_smoke` 命令目前只在本地手工执行有意义，CI 里没有对应作业。

协作服务在 CI 里跑在哪：它的用例就在 `workspace/agent/orchestrator/runtime/tests` 里（`test_collaboration_*.py`），由上面两个 Python 作业一起跑；协作服务的真进程用例自己派生 `python -m collaboration serve` 子进程并在结束时只回收自己启动的那几个。

## 12. 现在还不能做的事（环境层面的边界）

- **没有部署**：本机之外没有任何实例在跑这套服务；未配置 TLS、反向代理、进程守护或备份调度，CI 里也没有部署作业。
- **没有真实隔离**：`requires_real_data=True` 的派发准入需要真实隔离声明才能验，至今未创建也未验证任何 OS 级或容器级隔离，所以带真实数据的派发路径仍属未验收。
- **没有真实模型参与**：协作执行实例的 runner 仍是 `fake`，拆解与澄清的模型接缝未注入（`PlanService.planner`、`RequirementService.clarifier` 为空）。跑真实模型涉及费用，需单独确认。
- **档案的存放责任仍在人**：`backup` 只保证「这份副本被验证过」，不保证异地、加密与保留期；恢复必须紧跟 `restore-fence`，而「与备份之外的可信撤权记录核对成员/绑定」仍未实现。
