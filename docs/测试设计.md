# 项目测试设计（Test Design）

> 版本 v1.0 · 2026-09-28。基于当前代码盘点（后端 1090+ 用例，前端零覆盖）设计的
> 分层测试体系：现状盘点 → 缺口分析 → 分层策略 → 各层用例设计 → 实施优先级。
> 原则：测试跟随风险——token/安全/记忆是系统三大风险面，用例密度向其倾斜。

## 二、分层测试策略（金字塔）

```
            ┌─────────────┐
            │  E2E 冒烟    │  Playwright：七视图走查 + 关键用户流（少量、慢、真浏览器）
            │  (P2 计划)   │
          ┌─┴─────────────┴─┐
          │  跨层集成         │  TestClient 跨端点链路（dispatch→callback→audit）；
          │  (P1, 本期部分)   │  brain remote + 真 worker 子进程全链路
        ┌─┴─────────────────┴─┐
        │  组件/契约测试         │  RTL 组件测试（P0 本期）；types↔Pydantic 契约守护（P2）
      ┌─┴─────────────────────┴─┐
      │  单元测试（最厚）           │  后端已成型；本期补前端纯逻辑与 hooks（P0）
    └─────────────────────────────┘
```

工具选型：前端 **Vitest + Testing Library（RTL）+ jsdom**（与 Vite 5 同源零配置成本）；
E2E 用 **Playwright**（二期再上，避免一次性引入过多依赖）；契约守护用脚本比对
（P2：从 Pydantic openapi.json 抽字段 vs types.ts 断言）。

## 三、用例设计（按风险面分组）

### 3.1 前端（P0，本期实施）

**纯逻辑（cron.ts / utils.ts）**——最高性价比：
- `isValidCron`：合法（`0 9 * * 1-5`、`*/15 * * * *`、列表 `0,30 9 * * *`）/ 非法（越界 `99`、
  缺段、字母）；边界值 0/59、0/23、1-31、1-12、0-6
- `nextRuns`：`*/15` 命中 :15/:30/:45 边界；`0 9 * * 1-5` 跳过周末；日/周双受限取或语义；
  结果单调递增；非法表达式返回 []
- `timeAgo/formatTime`：秒/分/时/天边界、无效输入返回 '-'

**hooks（useTaskEvents）**——实时链路核心：
- SSE 事件追加时间线（status/callback/done 三类，坏帧忽略）
- snapshot+终态 → 主动关流（channel=off）
- done 事件 → 刷新任务记录 + 通知 onChange
- EventSource onerror → 降级 5s 轮询（channel=poll）
- 终态任务不建订阅；空 task_id 不建订阅
- 卸载时清理（无泄漏）

**组件（RTL）**：
- `ApprovalBar`：渲染裁决理由/命中规则/原指令；放行（approved=true 显示新任务 id）；
  修订放行（带 prompt）；approved≠true 显示失败原因且保留输入；拒绝走 confirm
- `UsageCard`：tokens/turns/cost/缓存命中率渲染与 '—' 兜底；命中率 = read/(read+input+creation)
- `StatusBadge`：七状态→颜色语义映射（awaiting_approval 必须 amber）
- `TaskDetailDrawer`：非终态打开时出现 SSE 通道指示；终态不订阅（channel=off）
- `Memory/ProposalCard`（P1）：三视角投票进度渲染、pending 才有投票按钮、diff 双栏

### 3.2 runtime 跨层集成（P1，本期实施 /audit）

- **/audit 端点**：空文件/不存在 → []；正常 JSONL 读取（新→旧）；stage/decision 过滤；
  坏行跳过；limit 截断；ORCH_AUDIT_LOG 环境变量覆盖路径
- **dispatch → callback → audit 串联**（复用现有 fake http 基建）：任务终态后审计里能找到
  对应 task_id 的 dispatch + product_check 记录
- **approve 流程**：awaiting_approval → 修订放行（重过检）→ 新任务创建 → 审计 approve 记录

### 3.3 全链路 E2E（P2，规划）

- brain(remote, 随机端口) + 真 worker 子进程（Fake runner）→ dispatch → 轮询 → artifact
  回读 → callback → 取消传播 → 审计断言。现有 worker/tests/test_e2e_artifact 是雏形，
  升级为 runtime 侧跨进程版
- **Playwright 面板 E2E**：种子数据 + 七视图冒烟（导航/审批操作/记忆编辑/提案 diff）+
  三视口不破版检查。依赖面板 dev server，标记为 `@slow` 单独跑

### 3.4 契约守护（P2，规划）

- 脚本：brain openapi.json 的 TaskRecord/ScheduleRecord/ProposalRecord 字段集合 ⊆
  types.ts 对应 interface 字段集合（防"后端加字段前端不显示"的静默漂移——面板三期
  的 approval 字段即此类问题）
- 挂 CI：后端测试产出 openapi.json → 契约比对 → 不一致即红

### 3.5 后端补强点（P2，非本期）

- security_guard LLM 增强路径目前只测降级；mock LLM 会话补 verdict 合并用例
- experience_store 并发写（多线程派发）下的淘汰竞态
- task_scheduler 与 retry_manager 的时间推进测试（fake clock 已有基建）

## 四、实施与验证标准

| 层 | 命令 | 标准 |
|---|---|---|
| 后端 | `python -m pytest workspace/agent/orchestrator/runtime/tests agent_core/tests worker/tests` | 全绿（当前 1090+） |
| 前端单测 | `cd web && npm test` | Vitest 全绿（本期新增 ~30 用例） |
| 前端构建 | `cd web && npm run build` | tsc 0 错误 |
| E2E | （P2）`npx playwright test` | 七视图冒烟通过 |

门禁建议：CI 串行跑 后端 → 前端单测 → 构建；E2E 手动触发。
