## 3. 主要解决原理与限制

### 3.1 缓存隔离与迟到响应

同样查询参数不代表同样数据来源。缓存键或前端请求必须绑定目录/连接/凭据范围；写入、切换连接或更新密钥时使旧请求失效，不能让晚到的数据重新写回当前范围。

后端工具缓存与前端连接守卫解决不同层面的问题。它们不代替团队身份和项目授权；共享 Key 也不是实名权限系统。

### 3.2 终态、重试和去重

执行体收到请求、业务任务取消、模型退出、费用结算是不同事件。状态修改要原子比较当前版本/状态，只有赢得提交的一方执行后续记账与事件通知。

Worker 去重需持久记录，不只用内存集合；重启后的未知任务应核对副作用，不能因为内存为空就再次执行。当前目录仍要求单 Worker 独占，TaskStore 也仍有单进程缓存限制。

### 3.3 预算与结算

并发准入应预占尚未发生的费用，完成后按同一执行标识结算。未知费用保留预占；取消 ACK 不能证明执行已经停止。旧 JSON 导入 SQLite 后应通过接口管理预算，不能改旧文件以为新账本会跟着变化。

SDK 预算和预占均非供应商支付硬截止；辅助模型与其他模式仍需统一归属。详见 [预算修复与回滚边界](Agent第二批修复_预算预占与持久结算_2026-10-13.md)。

### 3.4 Windows 终端与策略

`ls` 在 cmd 中不是通用内置命令。选择 PowerShell 时显式设置 UTF-8；回退 cmd 时按 OEM 编码解码，不能对所有 shell 固定 UTF-8。当前是按命令启动进程的终端，尚非完整 PTY/ConPTY。

工作区策略必须同时校验 JSON 语法和字段结构；有问题时整体回退默认策略，避免应用一半放宽配置。测试使用临时配置，不改个人真实策略文件。

### 3.5 个人理解沟通

模型负责出题/解释，程序负责结构校验、引用存在性、确定性评分与导航状态。回答或追问不推进题目，当前题和 revision 阻止迟到/并发写入覆盖进度。仅显式导航切题，全部补答后再确认最终评分。

证据匹配只能证明原文存在，不能证明题意或模型判断绝对正确。纠正意见须人工核实；资料 hash 变化后不再作为当前版本参考。此机制只在个人 HTTP/UI 启用，不能增加到团队派发。

## 5. 排查和验证入口

- 终端无输出/乱码：先确认实际 shell、cwd、退出码和编码，再查 [终端选择](../agent_core/terminal_shell.py) 与面板 WebSocket。不要先删除会话或全量清理工作目录。
- 会话/页面串用：确认连接 ID、地址、密钥更新、请求发起与落地范围，检查 [连接模块](../web/src/api/connections.ts)、[轮询](../web/src/hooks/usePolling.ts)、[会话选择](../web/src/api/brainSessions.ts)。
- 预算不释放：查询预占与原执行回执，确认是否费用未知/执行未结束；不要直接清空账本。
- 团队不规划/不执行：先检查 Planner/Runner 是否真实装配，别把协议 ready 或页面可打开视为模型已配置。
- 个人核验失效：检查需求/参数、资料版本、工作区、有效期及是否有新的严重偏差；历史记录仍可核查。

验证命令与测试范围见 [开发维护规范](开发与文档维护规范.md)。新增修复必须补充可复验步骤和剩余边界。
