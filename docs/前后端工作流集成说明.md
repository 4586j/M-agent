# 前后端工作流集成说明

> 记录 `D:\agent\web`（前端页面设计制作工作流）与 `D:\agent\back`（后端开发工作流）两套
> "可执行资产包"纳入多 agent 编排框架的方案、映射关系与使用方式。集成日期：2026-09-06。

## 1. 两套资产包是什么

两套资产包结构同构，均为"让 AI 按固定流程执行全流程任务并持续沉淀经验"的可执行资产：

| | web-expert（前端） | back-expert（后端） |
|---|---|---|
| 六阶段流水线 | S0 需求→spec → S1 原型 → S2 视觉设计 → S3 任务拆解+开发 → S4 走查与联调 → S5 上线与复盘 | S0 需求→spec → S1 领域建模与架构 → S2 数据与契约设计 → S3 任务拆解+开发 → S4 测试与联调走查 → S5 上线与复盘 |
| 卡点 | G1 spec / G2 原型 / G2b 视觉 / G3 开发自测 / G4 视觉走查 / G5 复盘关闭 | G1 spec / G2 架构 / G2b 数据与契约 / G3 开发自测 / G4 测试走查 / G5 复盘关闭 |
| 单一事实源 | `knowledge/design-tokens/tokens.json`（颜色/间距/字号） | `knowledge/conventions/response-and-errors.json`（响应/错误码/命名/分页） |
| 关键宪法原则 | P1 单一事实源、P2 复用优先、P3 规格先行、P9 积累义务、P10 偏移即停、P11 调研先行 | 同左，另有 P6 安全底线、P7 性能预算、P8 幂等一致性（API-First 契约冻结） |
| 积累池 | `knowledge/`（components / patterns / research / prompts / cases / decisions / checklists） | 同左（conventions 替代 design-tokens） |

## 2. 集成做了什么

1. **资产纳管**：将两套资产包的流程资产（`workflow/`、`knowledge/`、`tools/`、`AGENTS.md`、`README.md`）复制为框架技能：
   - `D:\agent\web` → `workspace/agent/skills/web-expert/`
   - `D:\agent\back` → `workspace/agent/skills/back-expert/`
   - 源仓库未做任何改动；**未随迁**：历史任务产物 `output/`（web 源仓库约 116M）、`.git`、`.qa` 测试残留。框架内任务产物写到技能目录下 `output/<项目名>/`。
2. **SKILL.md 适配层**：每个技能目录新增框架格式（frontmatter + triggers）的 `SKILL.md`，声明入口必读清单、派发 prompt 模板、框架对接规则。资产包原生 `AGENTS.md` 原样保留，作为 executor 开工的第一入口。
3. **大脑路由**：`skills/orchestrator/SKILL.md` 新增：
   - 「技能路由」一节：任务类型 → 技能映射（数据分析→data-expert、前端页面→web-expert、后端服务→back-expert、其他不挂技能）；**阶段即子任务**——每个流水线阶段是一次 executor 派发，卡点未过不派下一阶段。
   - ⑥ 执行调度：技能任务派发 prompt 必含 `[技能名] 阶段 / 输入 / 任务 / 退出卡点 / 产出位置`。
   - ⑦ 结果审核：技能任务额外核对卡点清单全过 + 按 AGENTS.md 第 4 节**积累回写**（P9，未回写 = 任务未完成，退回补做）+ 过程产物路径写入上下文记忆。
4. **executor 能力声明**：`.claude/agents/executor.md` 可用能力新增 web-expert / back-expert 条目（大脑派发 prompt 带 `[web-expert]` / `[back-expert]` 标记即触发）。
5. **安全规则扩展**：`security-rules/overrides/user.yaml` 新增 **R-USER-02**（`DROP TABLE/DATABASE`、`TRUNCATE TABLE` → block），落实 back-expert 宪法 P6"AI 执行破坏性操作前必须向用户确认"。生效规则 10 → 12 条。

## 3. 概念映射（资产包 ↔ 框架）

| 资产包概念 | 框架落点 | 说明 |
|---|---|---|
| pipeline 六阶段（S0~S5） | 大脑七阶段工作流的 ⑥ 执行调度 | 每个流水线阶段 = 一次 executor 派发；大脑维护阶段推进顺序 |
| gates 卡点（G1~G5） | 大脑 ⑦ 结果审核 | **业务卡点**（大脑/executor 对照 gates.md 自查），与 security-guard 的**安全关卡①②正交，两者都要过**；security-guard block 仍按大脑硬约束停给用户 |
| constitution（P1~P11） | 技能内上位依据 | 冲突时按宪法裁决；P6 安全底线叠加在 security-guard 规则之上 |
| knowledge/ 积累池 | 框架记忆层的跨任务部分 | 单次任务过程信息 → `skills/orchestrator/memory/context/<task-id>/`；跨任务复用资产 → 技能 `knowledge/` 池（P9 积累义务，⑦ 审核强制检查） |
| AGENTS.md | SKILL.md 适配层 + executor.md 能力声明 | 框架入口（triggers/路由）指向资产包原生入口 |
| 偏移日志（P10） | ⑦ 审核项 | spec 未覆盖需求 → 停下更新 spec 并记偏移日志，禁止静默实现 |

## 4. 使用方式

- **大脑路径**：接到前端/后端任务 → 阶段④拆解时按「技能路由」挂技能 → 阶段⑥按模板逐阶段派发 executor → executor 读技能 `SKILL.md`/`AGENTS.md` → 按当前阶段工作并对照 gates.md 自检 → 阶段⑦核对卡点与积累回写 → 通过后进记忆提炼。
- **Web 命令台路径**：在命令台派发时，prompt 写明任务类型（如"做一个登录页"/"新增订单接口"），大脑据此路由。
- **跳阶段**：已有设计稿/契约时允许从中间阶段进入，但 executor 必须在任务记录中写明跳过原因与替代交付物来源（两套 pipeline 首部规则）。

## 5. 注意事项

- **源仓库同步**：`skills/web-expert`、`skills/back-expert` 是集成时刻的快照。源资产包后续演进（宪法/流水线/模板更新）需手动同步进来；反向地，框架内任务的积累回写发生在框架副本的 `knowledge/`，勿回写源仓库造成分叉。若要消除双份维护，后续可改用 git subtree 或符号链接方案（Windows 下符号链接需开发者模式，暂用复制）。
- **remote 模式部署**：worker 跨主机部署时，executor 在 worker 上要读技能文件，需把 `workspace/agent/skills/` 一并随 worker 部署；否则应将所需流程资产内联进派发 prompt。
- **产物体积**：技能目录只存流程资产（各约 216K）；任务产物（页面/服务代码）写在各技能 `output/<项目名>/`，若产物含 node_modules 等重目录，注意 gitignore。
- **安全规则验证**：R-USER-02 已验证可命中 `DROP TABLE users;`、`drop database test`、`TRUNCATE table orders`，对普通 SELECT 无误报；规则引擎大小写覆盖用内联 `(?i:...)` 实现（规则引擎 `re.search` 未开 IGNORECASE）。
